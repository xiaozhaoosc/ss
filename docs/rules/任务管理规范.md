# 任务管理规范 (Task Management Protocol)

## 1. 目的
规范任务的创建、追踪、验证与归档流程，确保每个任务都有迹可循，状态清晰。

## 2. 文件命名规范
所有任务文件必须存放在 `docs/tasks/` 目录下。

**命名格式**：
`task_YYYYMMDD_HHmm_任务描述及编号.md`

**示例**：
- `task_20260203_2100_App完整性检查_01.md`
- `task_20260204_0930_后端API对接_02.md`

## 3. 文件内容模板
任务文件应包含以下核心部分（请直接复制使用）：

```markdown
# 任务: [任务名称]

## 📅 进度与待办 (Progress & Todo)
- [ ] **分析**: [任务点1]
- [ ] **开发**: [任务点2]
- [ ] **自测**: 验证功能是否符合预期
- [ ] **归档**: 清理临时文件，更新文档

## 🔍 自测与验证 (Verification)
在此记录验证步骤和结果：
1.  **测试用例 A**: [描述操作及其结果]
2.  **测试用例 B**: [描述操作及其结果]

## 📝 复查与反馈 (Review)
- [ ] 代码审查通过
- [ ] 功能验收通过

```

## 4. 流程状态
1.  **新建 (New)**: 创建文件，列出待办项。
2.  **进行中 (In Progress)**: 逐步勾选待办项，记录开发过程中的关键决策。
3.  **已完成 (Done)**: 所有待办项完成，自测通过。
4.  **已归档 (Archived)**: 任务结束，文件留存备查。

## 5. 归档策略
定期整理 `docs/tasks/` 目录，可将过期的旧任务移动至 `docs/tasks/archive/` 文件夹中。
