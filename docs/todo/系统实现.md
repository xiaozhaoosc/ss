# 4 系统实现 - 深度技术栈解析

> [!NOTE]
> 本章节旨在深入分析 **Small Steps (小步)** 系统的底层实现细节方案。系统不仅是一个功能集合，更是一套融合了 **ADHD 心理学模型** 与 **现代分布式架构** 的工程实践。

---

## 4.1 全栈架构 2.0: 动力中枢与双端

系统采用了典型的 **云-网-端** 架构，并针对弱网与高频交互场景进行了深度优化。

*   **后端中枢 (smallsteps-api)**:
    *   **框架**: 基于 Spring Boot 3.5.x 与 RuoYi-Vue-Plus 核心架构。
    *   **鉴权**: 集成 **Sa-Token**。支持多端（App/Admin）登录状态共享、JWT 刷新以及精细到“家庭”单位的长连接权限隔离。
    *   **异步化**: 使用 Redis 队列处理 AI 拆解任务，确保 C 端（孩子端）的秒速响应。
*   **管理大脑 (smallsteps-ui)**:
    *   **技术**: Vue 3 (Composition API) + Vite 4 + TypeScript。
    *   **特性**: 模块化插件设计，后端通过 `smallsteps-generator` 动态产出 CRUD 页面，极大提升了模版库的扩展性。
*   **交互终端 (smallsteps-app)**:
    *   **技术**: UniApp X (Vue 3 模式)。
    *   **原生性能**: 针对 Android/iOS 深度优化，确保在低性能设备上也能流畅显示复杂的“能量条”动画。

## 4.2 核心业务逻辑实现

### 4.2.1 Task Crusher (任务粉碎机) 算法
**核心挑战**: ADHD 儿童难以处理“模糊的大型任务”。
**实现方案**:
1.  **递归拆解**: 在 `ss_parent_task` 中引入 `parent_task_id`。
2.  **AI 驱动**: 当家长输入“收拾书桌”时，后端通过 **AI 中枢** 发起请求，Prompt 模板如下：
    > “请将『收拾书桌』拆解为 3-5 个具体的原子动作，每个描述必须为『动词+名词』，如『捡起废纸』，适合 8 岁 ADHD 儿童。”
3.  **状态机控制**: 复合任务的完成度由其所有子任务的状态自动计算。

### 4.2.2 Scaffolding (支架式辅助) 机制
**实现方案**:
*   **提示降级 (Fading)**: 系统记录孩子完成某类任务的“独立性评分”。
*   **逻辑控制**: 在 API 层，如果连续 5 次无需家长干预独立完成，下一次该任务的 `prompt_level` 将自动降低 1 级（例如：由语音引导降级为单纯的文字提醒）。

### 4.2.3 实时交互: WebSocket + SSE
**业务场景**: 孩子完成任务并点击“我做好了”，家长的手机需**即时**同步并弹出审批窗口。
*   **WebSocket 链路**: 建立 `Device-Gateway-Parent` 的实时长连接。
*   **降级方案**: 若 WebSocket 断连，系统透明回退到短轮询或 Server-Sent Events (SSE)，确保消息必达。

## 4.3 AI 中枢与 Mind Echo 情感模型

系统集成了一套通用的 **AI 路由机制** (基于 Spring AI 思想)。

*   **Mind Echo (情感回响)**:
    *   通过对孩子语音输入的 ASR（语音转文字）结果进行分析。
    *   检测关键词中的“挫败感、抗拒、喜悦”波动。
    *   **自动反馈**: 若检测到高频挫败感词汇，系统会自动给家长端推送：“Leo 在第 3 步似乎遇到了困难，建议给予口头鼓励或协助。”

---

## 4.4 移动端 UI 交互设计实现 (UX Logic)

为了减少 ADHD 儿童的视觉负担，App 端实现了以下特殊组件：

1.  **动态能量系统 (Energy Bar View)**: 
    *   不显示冷冰冰的数字进度，而是用填充颜色的“能量瓶”来通过 CSS Transition 实现视觉流体效果。
2.  **无压导航布局**:
    *   单屏只处理**一个**原子任务。
    *   取消复杂的 Tab 切换，采用“线性卡片流”设计。操作反馈延迟控制在 100ms 以内（即时反馈）。

## 5 安全与隐私隔离

> [!IMPORTANT]
> **数据边界**: 系统在 MyBatis-Plus 层配置了 **数据权限插件**。
> `parent_id` 与 `child_id` 将被强制注入所有查询条件，即使 API 漏洞也无法跨家庭越权访问敏感的情绪数据。
