# 4 系统实现 - 深度技术栈解析

> [!NOTE]
> 本章节旨在深入分析 **Small Steps (小步)** 系统的底层实现细节方案。系统不仅是一个功能集合，更是一套融合了 **ADHD 心理学模型** 与 **现代分布式架构** 的工程实践。

---

## 4.1 全栈架构 2.0: 动力中枢与双端

系统采用了典型的 **云-网-端** 架构，并针对弱网与高频交互场景进行了深度优化。

*   **后端中枢 (smallsteps-api)**:
    *   **框架**: 基于 Spring Boot 3.5.x 与 RuoYi-Vue-Plus 核心架构。
    *   **鉴权**: 集成 **Sa-Token**。支持多端（App/Admin）登录状态共享、JWT 刷新以及精细到“家庭（Dept）”单位的数据权限隔离。引入了 RBAC 与 ABAC 结合的权限控制机制。
    *   **异步化**: 使用 Redis Stream 处理 AI 拆解任务与异步日志，确保 C 端（孩子端）的秒速响应，削峰填谷。
*   **管理大脑 (smallsteps-ui)**:
    *   **技术**: Vue 3 (Composition API) + Vite 4 + TypeScript + Pinia。
    *   **特性**: 模块化插件设计，后端通过 `smallsteps-generator` 动态产出 CRUD 页面，极大提升了模版库的扩展性。支持深色模式。
*   **交互终端 (smallsteps-app)**:
    *   **技术**: UniApp X (Vue 3 模式) + UTS。
    *   **原生性能**: 针对 Android/iOS 深度优化，使用 UTS 编写原生插件，确保在低性能设备上也能流畅显示复杂的“能量条”流体动画与 Lottie 特效。

## 4.2 核心业务逻辑实现

### 4.2.1 Task Crusher (任务粉碎机) 算法
**核心挑战**: ADHD 儿童存在执行功能障碍，难以处理“模糊的大型任务”（如“打扫房间”）。
**实现方案**:
1.  **树形数据结构**: 在 `ss_parent_task` 中引入 `parent_task_id`，支持无限级拆解。
2.  **AI 驱动拆解**: 
    当家长输入模糊指令时，后端调用大模型，使用 Few-Shot Prompting 策略：
    > "作为ADHD专家，请将『收拾书桌』拆解为3-5个具体原子动作。要求：1. 使用『动词+名词』；2. 动作具象化且立即可执行；3. 预估单个动作耗时不超过3分钟。输出JSON格式。"
3.  **状态流转**: 
    ```mermaid
    stateDiagram-v2
        [*] --> 待执行
        待执行 --> 进行中: 孩子点击[开始]
        进行中 --> 待审批: 孩子点击[完成]
        待审批 --> 已完成: 家长[同意]
        待审批 --> 进行中: 家长[驳回重做]
        已完成 --> [*]: 发放积分
    ```

### 4.2.2 Scaffolding (支架式辅助) 机制
基于维果茨基的“最近发展区(ZPD)”理论设计：
*   **辅助降级 (Fading)**: 系统记录孩子完成某类任务的“独立性评分”。
*   **自动调节策略**: 
    API 层的规则引擎判定：若某任务连续 5 次无需家长干预独立完成，该任务的 `prompt_level` 将自动降低 1 级（例如：由“全屏视频示范+语音引导” 降级为 “图文提示”，最终降级为“无提示文字”），逐步培养独立性。

### 4.2.3 实时交互: WebSocket + SSE 退化机制
**业务场景**: 孩子完成任务并点击“我做好了”，家长的手机需**即时**同步并弹出审批窗口，强化即时反馈（ADHD儿童极需即时奖励）。
*   **实时链路**: 建立基于 Netty 的 `Device-Gateway-Parent` 实时 WebSocket 长连接。
*   **高可用退化方案**: 
    若 App 处于后台被限制或网络波动导致 WebSocket 断连，系统透明回退到 Server-Sent Events (SSE)，若 SSE 亦不可用，则最后回退到短轮询，确保“审批请求” 100% 触达家长。

## 4.3 AI 中枢与 Mind Echo 情感模型

系统集成了一套通用的 **AI 路由机制** (基于 Spring AI 抽象)。

*   **Mind Echo (情感回响)**:
    *   **多模态输入**: 融合孩子的语音汇报 (ASR 转文本) 与操作行为特征（如某个界面的停留时间、点击频率）。
    *   **情感波动捕捉**: 通过微调的小参数语言模型（如 Qwen-1.5-7B-Chat），分析文本中的情绪极性（挫败、抗拒、兴奋）。
    *   **干预建议推送**: 
        若检测到高频挫败感词汇，系统触发异步事件 `EmotionAlertEvent`，给家长端推送：“Leo 在第 3 步『整理文具』似乎遇到了困难，情绪值为 -0.8，建议立即给予口头鼓励或协助。”

## 4.4 移动端 UI 交互设计实现 (UX Logic)

为了减少 ADHD 儿童的视觉负担（消除分心源）与工作记忆负担：

1.  **流体能量系统 (Energy Bar View)**: 
    *   抛弃传统的冷冰冰的数字进度条 (如 30/100)。
    *   使用 Canvas/WebGL 实现填充颜色的“能量瓶”，积分增加时伴随流体激荡动画与音效，提供极强的视觉与听觉正反馈。
2.  **无压管线布局 (Tunnel Layout)**:
    *   **单点聚焦**: 屏幕中心每次只显示**一个**原子任务，隐藏其余待办。
    *   去除复杂的 Tab 栏切换，采用类似 TikTok 的“垂直滑动卡片流”设计。操作反馈延迟严格控制在 100ms 以内（即时反馈）。

## 5 安全与隐私隔离

> [!IMPORTANT]
> **数据边界**: 系统在 MyBatis-Plus 层配置了 **DataPermissionInterceptor** (数据权限插件)。
> 所有的业务查询（如任务、积分、情绪日志）将被强制在 SQL 层面注入 `dept_id = {当前家庭ID}` 的条件过滤，确保即使发生越权 API 调用漏洞，也无法跨家庭访问敏感隐私数据。同时对用户手机号、密码采取国密 SM3/SM4 算法进行脱敏与加密存储。
