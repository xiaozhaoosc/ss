# 4 系统实现 - 深度技术栈解析

> [!NOTE]
> 本章节旨在深入分析 **Small Steps (小步)** 系统各核心模块的底层实现。我们不仅关注功能的实现，更关注在高并发家庭应用场景下的系统稳定性、隐私隔离与极低时延的交互体验。

---

## 4.1 全栈架构 2.0: 动力中枢与双端协作

系统采用了典型的 **云-网-端** 架构，并针对家庭内高频交互场景进行了深度优化。

*   **后端中枢 (smallsteps-api)**:
    *   **核心框架**: 基于 Spring Boot 3.5.x 与 MyBatis-Plus 极速开发包。
    *   **鉴权体系**: 集成 **Sa-Token** 实现分布式 Session 共享。支持“多端同步登录”，允许家长在后台（Web）与手机端（App）同时在线且保持权限一致。
    *   **异步化处理**: 使用 Redis 队列处理高开销的 AI 拆解请求，确保孩子在点击任务时获得“秒响应”的端侧体验。
*   **管理后台 (smallsteps-ui)**:
    *   **技术栈**: Vue 3 (Composition API) + Vite + Element Plus。
    *   **动态路由**: 根据 RBAC 模型，动态从后端加载权限菜单，确保机构管理员与普通家长的界面逻辑物理隔离。
*   **移动端 (smallsteps-app)**:
    *   **技术栈**: UniApp X (Vue 3 模式)。
    *   **设计原则**: 针对 ADHD 儿童优化。采用“单屏单任务”逻辑，配合 CSS 能量动画，实现视觉压力极小化。

## 4.2 核心业务逻辑实现

### 4.2.1 Task Crusher (任务粉碎机) 拆解算法
**核心挑战**: ADHD 儿童难以处理长周期、大目标的任务。
**实现策略**:
1.  **分级存储**: 数据库中 `ss_parent_task` 表存在递归关系。
2.  **AI 拆解中枢**: 当家长创建一个新任务时，后端发起一个异步 AI 请求。
3.  **Prompt 逻辑剖析**:
    > “请将『收拾屋子』拆解为 5 个具有操作性的微小任务。要求：每个任务必须包含『拿起、放好、擦掉』等具体动作，且顺序必须符合逻辑顺序。”
4.  **实时下发**: 拆解完成后，通过 WebSocket 实时推送到孩子的终端，由孩子进行分步“打标”。

### 4.2.2 Scaffolding (支架式辅助) 与 Prompt 降级
**实现策略**:
*   **进度自动识别**: 系统会计算孩子在某个原子动作上的平均停留时长。
*   **动态提示**: 若在某一步停留超过 5 分钟，APP 侧会自动触发预设在 `ss_parent_emotion_kit` 中的提示音及视觉引导。
*   **自动撤离 (Faded Prompt)**: 随着该任务的“连续成功次数”增加，系统会自动在后端降低该任务的提示优先级，引导孩子将外部指令内化为自身习惯。

### 4.2.3 实时交互: WebSocket 通信流
**场景示例**: 孩子完成任务审批请求。
1.  **触发阶段**: 孩子点击“我做好了”。
2.  **消息路由**: `smallsteps-api` 将该事件封装为 `WebSocketMessageDto`。
3.  **精准推送**: 利用 `sys_user` 中的家庭关联 ID，将消息仅推送给同家庭（同 `dept_id`）的家长，家长端即时弹出“任务待审批”悬浮浮层。

## 4.3 AI 中枢与 Mind Echo 情感回响模型

为了实现对孩子情绪的精准捕捉，系统集成了一套通用的 **AI 路由机制**。

*   **Mind Echo (情感感知)**:
    *   前端通过手机录波或文本输入捕捉孩子的反馈。
    *   **情绪评分体系**: 后端调用 AI 模型（如 DeepSeek V3）对文本进行语义打分。
    *   **预警机制**: 若分值持续走低（代表孩子产生抗拒心理），系统会生成一条预警记录，供家长在管理端的“干预评估报告”中快速阅览，修正干预强度。

## 5 安全与多家庭隐私隔离

> [!IMPORTANT]
> **多租户隔离模式**: 系统在底层配置了全局过滤器，通过 `dept_id` 将所有 SQL 查询条件进行硬性重写。
> 这意味着在代码层面编写 `select * from tasks` 时，系统会自动补充 `where dept_id = current_family_id`，从根本上杜绝了跨家庭数据泄露的风险。
