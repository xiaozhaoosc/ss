ADHD中小学生（儿童）行为习惯辅助系统设计与实现

摘要：注意缺陷多动障碍（Attention Deficit Hyperactivity Disorder, ADHD）是学龄期儿童群体中高发的神经发育障碍类型，其典型临床表征涵盖注意力维持困难、活动量过度以及行为冲动控制不足三个核心维度。受上述症状影响，患儿在学业进展、同伴社交及日常行为规范方面均面临不同程度的适应性困难。既有的干预路径以药物治疗与人工行为矫正为主，但前者伴随显著的生理副作用，后者受制于专业康复资源的稀缺性和家庭执行的可持续性瓶颈。伴随移动互联网与人工智能技术的深度渗透，数字化辅助干预已成为ADHD康复研究领域的前沿方向。然而，现有数字辅助工具普遍存在功能设计泛化的局限：多数系统停留在基础日程管理层面，缺乏针对ADHD患儿认知加工模式的定制化交互方案，在亲子协同干预、动态化激励策略以及行为数据闭环反馈等关键环节上仍有明显不足。

针对上述现实困境，本课题采用软件工程方法论，设计并实现了一套聚焦于ADHD中小学生行为习惯养成的多端协同辅助系统——"小步（Small Steps）"。系统整体采用前后端分离的分层架构，通过三个独立子系统的协同运作——儿童与家长共用的移动端应用（smallsteps-app）、面向平台运营的Web管理后台（smallsteps-ui）、以及承载核心业务逻辑的后端服务（smallsteps-api），构建了一个覆盖渐进式任务拆解、多维度激励反馈、专注力训练以及家庭协同管理的完整数字干预闭环。

在后端架构设计层面，核心服务基于Spring Boot 3.5.9框架与JDK 21运行环境构建。数据持久层集成MyBatis-Plus 3.5.14增强型ORM框架，实现了高效的实体映射与复杂条件查询封装；安全与权限管理层面引入轻量级开源框架Sa-Token 1.44.0，设计了面向管理员、家长、儿童三种差异化角色的细粒度鉴权体系；此外，系统集成Redisson分布式锁组件与Lock4j并发控制框架，以保障高并发场景下的数据一致性与业务原子性。数据库采用MySQL进行关系型数据持久化，配合Redis提供会话缓存与高频读写的性能支撑。

在前端设计与实现层面，移动端应用基于UniApp 3.0跨平台框架开发，深度整合Vue 3.5的Composition API编程范式与Pinia 2.x全局状态管理机制，创造性地实现了家长模式与儿童模式在同一应用内的无缝身份切换与差异化视图呈现。UI样式层采用TailwindCSS 3.4原子化CSS方案，满足ADHD儿童界面对高对比度色彩与低认知负荷布局的特殊设计要求。Web管理后台基于Vue 3.5与Element Plus 2.11组件库构建，集成ECharts 5.6数据可视化引擎与VXE-Table高性能表格组件，提供了涵盖用户管理、任务配置、行为数据看板及系统运维监控的全功能图形化管理界面。UI样式层采用UnoCSS即时原子化CSS引擎，在保持开发效率的同时实现了精确的样式控制。

系统的设计创新集中体现在两个维度：其一，将生成式大语言模型（LLM）的智能分析能力以旁路服务的形式嵌入后端业务流程，通过定时任务调度机制聚合儿童的多日行为数据（任务完成率、专注时长分布、情绪波动趋势），动态生成个性化的"每日寄语"与家长辅导话术建议，有效缓解了重复打卡带来的动机衰减；其二，在交互设计层面系统性地融入认知负荷理论与渐进式辅助（Scaffolding & Fading）理念，通过多模态数据可视化与家庭成员间的角色互动机制，引导家长从传统的"检查者"角色向"陪伴观察者"转型，从而在家庭系统层面重塑干预关系的正向动力学结构。

经过多轮功能测试与交互可用性验证，系统各业务模块运行稳定，前后端数据交互高效，页面渲染响应流畅，整体满足设计阶段制定的性能基准与业务需求指标。本课题的研发实践不仅为ADHD儿童的日常行为干预提供了一种可落地的轻量化数字工具，也为基于现代前端工程体系与智能后端架构的数字疗法类产品输出了一套具有参考价值的系统设计范式。

Design and Implementation of ADHD Behavior Support System for Children

Abstract: Attention Deficit Hyperactivity Disorder (ADHD) ranks among the most prevalent neurodevelopmental conditions affecting school-aged children, manifesting through core symptom clusters of sustained inattention, excessive motor activity, and impulsive behavioral regulation deficits. These symptomatic presentations impose substantial adaptive challenges on affected children across academic performance, peer socialization, and adherence to daily behavioral routines. Conventional intervention approaches, primarily pharmacotherapy and manual behavioral modification protocols, face inherent limitations including notable physiological side effects of medication, scarcity of professional rehabilitation resources, and compromised sustainability of family-based intervention delivery.

To address these multifaceted challenges, this research project employs software engineering methodology to design and implement "Small Steps" — a multi-terminal collaborative assistance system specifically targeting behavioral habit cultivation in primary and secondary school students with ADHD. The system adopts a decoupled front-end/back-end layered architecture, operating through three independent yet coordinated subsystems: a cross-platform mobile application serving both children and parents (smallsteps-app), a web-based administrative console for platform operations (smallsteps-ui), and a backend service layer hosting core business logic (smallsteps-api).

At the backend architectural level, the core service infrastructure is constructed upon the Spring Boot 3.5.9 framework operating on JDK 21 runtime. The data persistence layer integrates MyBatis-Plus 3.5.14 enhanced ORM framework, while the security and authorization layer employs the lightweight Sa-Token 1.44.0 framework to implement fine-grained role-based access control across administrator, parent, and child user categories. The mobile application leverages the UniApp 3.0 cross-platform framework with deep integration of Vue 3.5 Composition API and Pinia 2.x state management, achieving seamless identity switching between parent and child operational modes. The web administrative console is built upon Vue 3.5 and Element Plus 2.11 component library, incorporating ECharts 5.6 for data visualization and VXE-Table for high-performance tabular data rendering.

The system's design innovation is embodied in two principal dimensions: first, the integration of generative Large Language Model (LLM) analytical capabilities as a sidecar service within backend business workflows, enabling dynamic generation of personalized daily messages and parental coaching suggestions based on aggregated multi-day behavioral metrics; second, the systematic incorporation of Cognitive Load Theory and Scaffolding & Fading pedagogical principles into the interaction design layer, facilitating parental role transformation from conventional "inspector" to "companion observer" through multi-modal data visualization and family member interaction mechanisms.

Through multiple rounds of functional testing and interaction usability validation, all system business modules demonstrate stable operation with efficient front-end/back-end data exchange and responsive page rendering performance, meeting the design-phase performance benchmarks and business requirement specifications. This research contributes both a deployable lightweight digital intervention tool for daily ADHD behavioral support and a referenceable system design paradigm for digital therapeutic products built upon modern front-end engineering ecosystems and intelligent backend architectures.

Keywords: ADHD; Behavioral Intervention System Design; Decoupled Architecture; Spring Boot 3; UniApp; Vue 3

1 绪论

注意力缺陷多动障碍（ADHD）作为儿童发育阶段最为普遍的一类神经行为异常，其核心特征体现为持续性的注意力分配困难、过量的躯体运动以及难以抑制的行为冲动。处于义务教育阶段的患儿因上述症状的交互作用，在学业投入效率、日常生活自理技能培养及家庭亲子关系维护等方面均承受着超出同龄人的适应压力。传统干预体系以药物介入和线下行为训练为两大支柱，但药物副作用、康复资源地域分布失衡以及家庭执行方案难以标准化等结构性问题始终制约着干预效果的可持续性。在此背景下，融合移动计算平台与智能算法的数字化辅助干预（Digital Therapeutics, DTx）逐渐崛起为ADHD研究领域的新范式。然而，当前市面上的辅助应用大多停留在通用型效率工具的层面，缺少面向ADHD患儿独特认知加工模式的深度定制，且在家庭系统层面的协同设计上存在明显短板。本课题正是针对这一现存缺口，从系统设计与工程实现的双重视角出发，提出并落地了一套多端联动的行为习惯养成辅助系统。

1.1 研究背景

注意缺陷多动障碍（Attention Deficit Hyperactivity Disorder，简称ADHD），是儿童及青少年时期发病率最高的慢性神经发育类障碍之一。全球流行病学统计数据显示，学龄儿童中ADHD的患病率介于5%至7%之间，部分地区因筛查标准及诊断体系差异，报告的比例更为突出。该障碍的核心临床特征表现为三组与年龄发育水平不相称的行为症候群：注意力持续维持显著困难、运动活动量远超正常水平（即多动），以及行为决策前缺乏充分的后果评估（即冲动）。需要特别指出的是，ADHD并不直接损害患儿的智力功能，但它对执行功能（Executive Function）系统——包含工作记忆容量、情绪调节机制、内在动机激发以及计划组织协调能力——造成了弥散性的功能削弱，由此在日常生活层面引发连锁的适应性障碍。

在学校教育情境中，ADHD患儿频繁表现出难以维持课堂坐姿、注意力被无关环境刺激轻易牵引等典型行为；在家庭作业环节，严重的任务启动困难与拖延行为构成了家长每日面临的核心痛点，且作业的差错率显著高于同龄群体。在同伴社交维度，由于冲动行为控制能力薄弱，患儿容易在不恰当的社交时机打断他人谈话或产生肢体冲突，导致其在同伴关系网络中遭遇排斥与边缘化。长期持续的受挫体验极易使ADHD患儿衍生出自卑感、焦虑情绪乃至抑郁倾向等继发性心理健康问题。因此，如何借助技术手段为ADHD儿童提供有效的日常行为结构化支持，降低其认知加工负荷，辅助其逐步建立规律化的生活与学习节律，已成为一个兼具社会意义与技术挑战性的议题。

1.2 数字化行为辅助工具的应用价值与研究目的

在既有的ADHD临床干预体系中，药物治疗路径（以盐酸哌甲酯为代表的中枢兴奋剂类药物）虽能在短期内改善核心症状，但其在儿童群体中广泛应用所附带的食欲减退、睡眠节律紊乱、生长发育潜在抑制等副作用风险，持续引发医学界与家长群体的审慎关注。非药物的行为干预技术路线（如亲职管理训练 Parent Management Training，PMT），尽管被循证医学体系认定为长期有效的核心干预手段之一，但其实施门槛极高：一方面要求具备专业资质的临床心理工作者全程督导，另一方面高度依赖家长在日常家庭环境中长期保持高度一致、情绪稳定且科学规范的执行质量。现实中，大量家长自身承受着工作与生活的多重压力，加之专业心理学知识储备有限，在旷日持久的"督促—反抗"家庭拉锯中极易出现情绪崩溃，最终使干预过程陷入家长耗竭与患儿抵触的双向恶性循环。

正是在上述干预困境的推动下，数字化行为辅助工具（Digital Behavior Assistance Tools）展现出独特的应用价值。智能手机端应用程序天然具备全时段待命、客观无情绪波动干扰、行为数据自动精准记录等特性。将其引入ADHD家庭干预场景，能够承担起"第三方缓冲介质"的结构性角色：一者，通过游戏化交互与即时正向反馈机制，精准匹配ADHD儿童多巴胺分泌偏低导致的内在动力不足问题，将枯燥的日常任务转化为具有吸引力的挑战序列；二者，系统性地分担家长在传统模式下承担的"监工"式监督职能，减少亲子之间的直接言语摩擦，释放家长的心理能量使其得以聚焦于情感支持与陪伴等更具建设性的家庭功能发挥，从而在结构层面促进家庭动力学（Family Dynamics）的良性修复。

基于上述分析，本课题的核心研究目的在于：设计并实现一套专门面向ADHD中小学生群体的、多端协同的、兼具工程可落地性与心理学理论支撑的行为习惯数字辅助系统。

1.3 面向ADHD儿童的技术干预需求缺口分析

尽管移动应用市场上已大量涌现标榜"时间管理"、"日程规划"、"番茄工作法"等功能卖点的效率类应用产品，但当这些面向普通用户群体设计的通用工具被应用于具有特殊脑神经基础的ADHD患儿时，普遍出现多维度的适配失效：

（1）界面认知负荷过高：通用型效率应用的界面设计通常追求功能齐全，导致信息架构层级深、视觉元素堆叠密集。对于前额叶皮层功能发育相对滞后、"信息噪声过滤"能力显著受损的ADHD儿童而言，这种界面范式构成了灾难性的视觉与认知超载源。

（2）缺乏面向"执行功能障碍"的细粒度任务拆解引导：ADHD患儿的任务启动困难（Task Initiation Deficit）往往根源于他们将一个宏大目标（如"做作业"）感知为一个不可分解的整体巨石。市面上的通用工具极少内置面向这一认知特征的强制性、结构化的前置微步骤拆解流程，导致辅助功能在实际使用中形同虚设。

（3）激励反馈机制僵化且以负向关注为主：大多数工具采用冰冷的数据汇总进行反馈（"今日2项任务未完成"），这种以缺失为焦点的表述方式极易激活ADHD患儿本已脆弱的挫折感与习得性无助心理。他们真正需要的是能够包容失败、积极捕捉并庆祝每一个微小进步（Small Steps）的即时温暖反馈体系。

（4）缺少家庭系统层面的协同设计：现有工具几乎将全部设计焦点压在执行端（儿童）的行为矫正上，完全忽视了对另一关键角色——家长——的心理赋能与角色引导。在缺乏家庭系统视角的协同设计下，工具沦为"电子版催促清单"，难以触及家庭关系结构性改善的深层目标。

综合以上缺口分析，当前市场亟需一款真正深入理解ADHD儿童认知行为模式、以降低认知负荷与情感陪伴为核心设计理念、并能在家庭系统层面实现双端协同联动的专业化辅助系统。

1.4 国内外研究现状与发展趋势

1.4.1 传统行为干预与认知疗法的局限性

自二十世纪中后期以来，认知行为疗法（Cognitive Behavioral Therapy, CBT）及各类亲职教育训练计划在ADHD症状改善方面积累了坚实的循证基础。在结构化的临床情境中，治疗师运用角色扮演、代币经济制度（Token Economy）等操作化技术，帮助患儿及其家庭系统在行为微观层面实施重塑。然而，这些方法面临着从受控临床环境向自然家庭情境进行行为泛化（Behavioral Generalization）时的系统性衰减难题。家长作为日常环境中的"非专业执行代理人"，在缺乏持续专业督导与标准化工具支撑的条件下，极易受到自身情绪状态波动的干扰，使得行为强化与消退的操作标准发生不可控的偏移，最终导致干预效果的侵蚀甚至逆转。

1.4.2 数字疗法在ADHD干预中的探索与发展

近几年，国际医疗技术领域对数字疗法（Digital Therapeutics, DTx）在神经精神类疾病中的应用开展了深入探索。2020年，美国食品药品监督管理局（FDA）正式批准了全球首款针对ADHD的处方级数字干预产品EndeavorRx（一款基于游戏化设计的认知训练应用），该里程碑事件标志着游戏化数字干预路径获得了主流医疗监管体系的认可。在软件应用生态中，欧美研究团队陆续推出了旨在增强ADHD儿童时间感知锚定、提供日程结构化规划的辅助系统原型。

反观国内研究现状，面向ADHD群体的数字辅助产品开发尚处于起步阶段与快速探索期的交汇点。市面上的干预工具以在线量表评估、知识付费课程以及基础打卡类应用为主要形态。虽然部分产品尝试引入了积分奖励等游戏化元素，但在交互细节的精细化打磨以及面向神经多样性（Neurodiversity）群体的定制化设计方面，仍显粗糙与不成熟。

1.4.3 现有研究不足与本系统的设计突破点

综合国内外的研究进展与产品实践可以发现，借助移动互联网平台向ADHD家庭提供行为干预辅助已成为确定性趋势，但面向中国ADHD中小学群体，仍然缺乏一套在交互设计深度与家庭系统协同广度上均能满足需求的综合解决方案。

本课题设计的"小步（Small Steps）"系统正是在这一研究空白地带中提出的。与现有方案相比，其核心设计突破体现在以下三个层面：

（1）尊严优先的人本化交互设计理念：彻底摒弃居高临下的"监督者"预设视角，一切界面元素与交互流程的设计均以"平辈陪伴者"的关系定位为出发点，刻意避免对任务失败的过度惩罚性暴露，维护患儿在使用过程中的心理安全感与自尊。

（2）融入LLM智能分析的渐进式辅助策略（Scaffolding & Fading）：系统不仅具备常规的任务提醒功能，更在后端集成了大语言模型的行为数据研判能力。通过对儿童完成任务的关键卡点进行多维度分析，系统能够动态调整辅助强度——在习惯养成初期提供高密度支持，在行为模式趋于稳定后自动执行辅助退出策略，最终目标指向患儿的行为自主性培养。

（3）采用现代化全栈工程架构的前瞻性技术选型：系统采用Vue 3与Spring Boot 3等当前业界前沿的技术生态进行全栈工程化开发，利用UniApp框架解决移动端跨平台兼容性问题。通过严谨的全链路行为数据采集与可视化呈现，打破了传统人工干预模式下行为数据难以量化追踪的"黑盒"困境。

1.5 主要研究内容与目标

本课题围绕ADHD中小学生在日常生活与学业场景中面临的实际行为管理困难，针对现有数字辅助工具在交互定制化与家庭协同设计上的不足，运用现代软件工程方法论与前后端分离架构体系，以系统设计与工程实现为主线，详细论述了一套涵盖移动端（儿童+家长共用）与Web管理后台的"多角色业务闭环"辅助系统的完整研发过程。具体研究内容与目标包括：

（1）认知心理学理论到前端交互设计的转化实践：探索如何将"降低认知负荷"、"代币经济强化"、"即时正向反馈"等心理学抽象概念，借助UniApp与Vue 3技术栈转化为可触达、可交互的UI组件与交互流程（如环形进度条番茄钟、微动效奖励动画、低饱和度色彩语言等），形成面向ADHD特殊群体的前端设计范式。

（2）前后端分离架构下多角色安全体系的设计与验证：深入设计基于Spring Boot 3与Sa-Token的细粒度鉴权方案，在保证系统高并发访问能力的前提下，实现管理员、家长、儿童三类角色在API接口层与数据访问层的双重隔离防护，并利用Redis构建可靠的分布式会话状态管理。

（3）大语言模型驱动的智能反馈服务设计：研究如何在后端系统中以异步旁路服务的形式稳定接入LLM能力，基于儿童的阶段性行为数据聚合结果，自动化生成具有同理心导向的个性化寄语与家长辅导话术建议，探索生成式AI在数字行为辅助领域的工程化实践路径。

（4）完整的系统工程化设计与实现闭环：从需求分析、系统总体架构设计、数据库建模、API接口规范到多端前端实现与系统测试验证，完整展示一套符合软件工程规范的设计类毕业设计全流程。


2 系统分析

在进入详细设计阶段之前，本章从技术可行性论证、功能性需求提取与非功能性质量属性规约三个维度对系统进行全面分析。通过精确的需求对齐与技术论证，为后续的架构设计与编码实现奠定可靠的决策基础。

2.1 技术可行性分析与技术选型

"小步"系统的工程化建设在技术选型与理论支撑两个层面均开展了严谨的评估与论证。工程层面，选用了当前业界成熟度高且具有演进前瞻性的前后端技术栈组合；理论层面，系统性地借鉴了认知心理学与家庭系统治疗领域的成熟研究成果。系统整体遵循B/S（Browser/Server）与C/S（Client/Server移动端）混合部署的前后端分离架构范式，各端之间通过标准化的RESTful API实现松耦合的数据通信。

2.1.1 后端核心框架选型 (Spring Boot 3 + MyBatis-Plus)

系统后端核心服务选用Spring Boot 3.5.9作为基础框架。Spring Boot 3作为Java生态中最为主流的应用开发脚手架，在依赖自动管理、约定优于配置以及内嵌服务器等方面具备成熟的工程化优势。本系统选择3.x版本线主要基于其对JDK 21长期支持版本的原生适配以及对Spring Framework 6的深度整合，这为后续引入虚拟线程（Virtual Threads）等JDK新特性预留了可能性。在系统中，Spring Boot框架承载了全局异常统一处理、跨域资源共享（CORS）策略配置、以及面向前端的标准化响应结构封装等基础设施层职责。

在数据持久化层面，系统集成了MyBatis-Plus 3.5.14增强型ORM框架。本系统中存在大量围绕"任务生命周期流转"与"用户行为数据多维统计"的复杂查询场景，直接使用原生MyBatis将产生大量重复性的XML映射配置（Boilerplate Code），而全自动化的JPA规范在面对多表关联与动态条件组合时又缺乏足够的SQL层定制灵活性。MyBatis-Plus恰当地在这两极之间取得了工程平衡：其内置的通用Mapper接口与LambdaQueryWrapper类型安全条件构造器，将基础单表CRUD操作的代码量压缩至最小；同时保留了对复杂SQL的完全自定义能力，保障了项目快速迭代过程中数据访问层的代码质量与开发效率。

2.1.2 移动端CSS框架选型 (TailwindCSS)

面向移动端的UI样式构建引入了TailwindCSS 3.4原子化CSS框架。在传统的CSS开发实践中，开发者需为各类UI组件编写独立的选择器规则，极易引发命名冲突与全局样式污染问题。TailwindCSS采用Utility-First（效用优先）设计范式，将flex、pt-4、text-center、rounded-lg等原子级样式类直接组合于Vue模板标记中，实现了"所写即所得"的内联式样式声明。

这一选型对于ADHD儿童端界面的设计实现具有特殊的适配价值：ADHD导向的界面设计对色彩对比度梯度（如text-gray-800与bg-white的明度差异控制）以及微交互动效参数（如transition-all duration-300 ease-in-out的动画缓动曲线）有着极为严苛的精确度要求。TailwindCSS使开发者能够直接在Vue组件模板中快速构建并精细调校这些视觉表现参数，彻底消除了"修改一处样式引发全局布局崩塌"的样式污染风险。此外，框架内置的PostCSS编译管线在生产环境构建时仅打包实际引用的样式类名，有效控制了移动端应用包体积。

2.1.3 安全认证框架选型 (Sa-Token)

在访问安全与权限隔离维度，考虑到系统需同时服务"超级管理员、家庭主账号（家长）、附属子账号（儿童）"三类认知模式与操作权限存在显著差异的角色群体，Spring Security虽功能全面但配置复杂度过高，学习曲线陡峭，与本系统快速迭代的工程节奏不匹配。经过技术评估，系统最终选用了国内开源的高性能轻量级权限认证框架Sa-Token 1.44.0。

Sa-Token的核心工程优势在于其API设计高度贴合开发者直觉——仅需StpUtil.login(id)一行代码调用即可完成完整的会话建立流程。在此基础能力之上，系统充分利用其内置的拦截器引擎（SaInterceptor）与自定义注解声明式鉴权机制（如@SaCheckRole("PARENT")），在Controller方法级别实现了精准的接口访问控制。配合Redis作为Token存储后端，Sa-Token自动完成了会话的无状态分布式校验、同设备类型下多账户互踢控制以及敏感操作的二次认证保护，以极低的代码侵入性为系统构筑了纵深防御体系。

2.1.4 心理学与教育学理论基础

技术选型服务于人本需求。ADHD行为干预是一项典型的交叉学科课题，本系统的UI视觉设计理念、交互流程定义原则以及后端业务判定逻辑，均以如下心理学与教育学理论框架作为设计准绳。

（1）认知负荷理论对UI/UX设计的指导

认知负荷理论（Cognitive Load Theory, CLT）揭示了人类工作记忆（Working Memory）容量的固有局限性。对于ADHD患儿群体而言，其前额叶皮层的发育阶段性滞后导致其信息噪声过滤、复杂信息并行处理以及任务上下文切换的认知能力显著弱于同龄对照组。当软件界面充斥过量的按钮、文字说明与高饱和度色彩块时，将诱发患儿外在认知负荷（Extraneous Cognitive Load）的急剧攀升，直接触发使用厌倦与抵触行为。

在"小步"系统的前端设计中，全面贯彻了"认知卸载"的设计哲学。例如：儿童端待办任务展示页面每屏仅呈现一个核心任务，背景采用低饱和度的柔和色调；任务描述优先使用图形化Icon配合极简文案（如用水杯图标替代"喝水200ml"的纯文字描述）。这种"视觉简约优于信息完备"、"单任务线程呈现"的设计原则，最大限度地释放了ADHD患儿有限的认知加工带宽，使其能够将有限的注意力资源集中投射于当前任务的执行本身。

（2）渐进式辅助理论与正向反馈循环机制

渐进式辅助理论（亦称"脚手架理论" Scaffolding），源自维果茨基关于"最近发展区"的经典论述。该理论主张：当个体学习新技能或面对适应性挑战时，来自外部的辅助力量应当如同建筑脚手架一般——在能力薄弱阶段提供结构化的强力支撑，随着个体能力的逐步成长再有计划地拆除支撑构件（Fading），最终实现个体的行为自主。

在系统行为逻辑中，当一项全新的长期习惯养成目标（如"按时就寝"）被初始化时，系统将在初期阶段密集触发视觉与听觉的双通道提醒介入，并配置较高权重的代币奖励激励。当系统通过持续多日的行为数据监测确认该任务已达到稳定的按时高质完成水平后，将由AI分析模块研判触发辅助降级策略（Fading Strategy）——逐步减少前置提醒的触发频率与强度，引导外在的技术强制力向内在的行为惯性自然过渡。这种动态化的支撑强度调整机制，有效预防了患儿对数字辅助工具形成不可逆的路径依赖。

与此同时，系统借鉴操作性条件反射的行为强化原理，采用微小、高频、包含随机性的即时奖励策略（如专注模式结束时触发的星星掉落动画、碎片收集机制），替代传统的延迟结果奖励模式，构建起稳固的正向多巴胺反馈循环（Positive Feedback Loop），从神经化学层面增强患儿对抗任务枯燥感的持久力。

（3）系统家庭动力学与家长角色重塑

传统ADHD干预实践中存在一种隐性的系统偏差：过度聚焦于"矫正"患儿个体行为，而忽略了家庭作为整体微生态系统对干预效果的决定性影响。在典型的ADHD家庭关系结构中，父母长期扮演"高压监控者"与"惩罚执行人"的角色，自身陷入情绪耗竭状态的同时，更容易与步入青春前期的患儿发生高强度的情感对抗。这种对立性的关系架构使得一切来自家长的辅助行为都天然带有"被动抵抗"的底色。

本系统的设计意旨正在于重构这一脆弱的家庭动力学结构。通过将系统定位为亲子之间的"缓冲介质"，把原本由家长直接承担的"记录、催促、检查"等高情绪成本操作，完全委托给客观、无情绪波动的数字化应用以游戏化形式完成。此时，家长端的应用角色转化为"数据观测台"——家长通过系统反馈看到的不再是"你孩子又没做作业"的指责性信息，而是"今日专注力表现较昨日下降20%，可能与睡眠不足有关"的客观分析。如此一来，家长的角色自然从"裁判"过渡为更具包容性的"观察者"与"情感陪伴者"。这种将亲子关系从"对立的裁判—选手"转型为"并肩的队友—共同面对挑战"的结构性修复，是干预方案在家庭环境中获得长效执行力的根本性理论支撑。

2.1.5 操作可行性评估

系统面向ADHD儿童群体设计的交互逻辑严格遵循"零学习成本"原则：核心操作路径不超过三步点击深度，界面视觉元素采用高对比度与大触控热区设计，完全契合目标用户群体的认知能力和操作习惯阈值。

2.2 系统需求分析

在明确了技术选型方向与指导性理论框架之后，本节进入系统的需求分析阶段。需求分析作为软件工程生命周期中的关键管控节点，直接决定了系统建设的功能边界与交付价值。本节将首先对"小步"系统的双重目标受众进行深度画像刻画，在此基础上推导出系统在交互功能维度与非功能性能维度的具体需求规格。

2.2.1 目标用户群体画像分析

本系统的核心服务对象构成一个典型的"双核用户架构"：即行为干预的直接接收方（ADHD儿童）与干预实施的辅助管理方（家长或监护人）。这两个用户群体在生理发育基础、心理预期取向以及对数字工具的功能诉求上存在根本性差异，需要分别进行画像建构。

（1）ADHD儿童与青少年的认知行为特征画像

基于对国内多家特殊教育机构及儿科发育行为门诊的调研性信息采集，6至15岁年龄段的ADHD学龄群体呈现出如下具有共性的行为特征模式：注意力维度层面，对高多巴胺刺激源（如竞技类电子游戏、短视频流媒体）能够展现出超常水平的专注力投入（Hyperfocus），但面对日常重复性生活任务（如洗漱流程、书包整理、课文背诵），注意力窗口通常不超过5至10分钟即出现显著衰减；时间管理维度层面，患儿普遍缺乏对"预计耗时"的内部评估锚点，表现为"磨洋工"式的非效率消耗或截止时限前的突发性恐慌两种极端模式；情绪调节维度层面，相较于神经典型发育（Neurotypical）的同龄儿童，他们的挫折耐受阈值显著偏低，极易因微小的任务失败触发情绪崩溃反应或攻击性回避行为。

基于上述特征画像，儿童端应用的最低设计准入标准锚定为：零认知学习成本、极高的操作容错宽容度、以及即时性的多模态（视觉+听觉）正向奖励反馈。该终端的体验定位绝不能向"复杂的效率管理工具"方向偏移，而应被构建为一个"深度理解用户心智模式的陪伴式游戏化界面"。

（2）家长群体的管理诉求与核心痛点

陪伴ADHD患儿成长的家长群体同样是本系统不可忽视的关键用户。他们的核心使用痛点集中表现为：监督疲劳与精力透支——每日需重复发出数百次相同的行为指令（如"去刷牙""坐直"），导致严重的情绪耗竭（Caregiver Burnout），进而高频触发家庭冲突；执行过程不可见与"虚假完成"困境——家长在家庭辅导中极容易被孩子敷衍了事的"做完了"蒙蔽，缺乏对任务实际完成质量与注意力投入时长的量化监测手段；渴望科学化的实操指导而非泛化的教育建议——家长迫切需要的不是"要多鼓励孩子"这类笼统建议，而是"当孩子此刻情绪崩溃时，我应该用什么具体话术回应"这样的场景化方案。

因此，家长端的系统设计必须围绕行为数据的结构化可视化呈现、任务的高效创建与分发、以及基于AI的智能辅助话术生成为核心展开，使其成为家长的"认知外脑"与"情绪稳定锚"。

2.2.2 系统功能性需求

依据多角色业务流向分析，系统在功能域上清晰划分为三个紧密耦合的子模块：儿童移动端、家长移动端以及Web管理后台终端。

（1）总体业务流程概述

系统的核心业务数据流以"任务"实体为中枢展开闭环运转：家长在移动端或管理后台创建任务并分配至指定日期的儿童账户；儿童端接收任务指令，通过进入专注模式执行任务，完成后触发奖励结算逻辑；行为数据实时回流至后端服务并更新至家长端数据看板；后台的AI模块基于定时调度策略扫描聚合阶段性行为数据，生成辅助建议与个性化寄语，预备次日的干预内容推送。

（2）儿童端核心功能需求

儿童端定位为行为数据产生的首要触发入口，功能设计遵循极简化准则，核心围绕以下三个功能点展开：
任务卡片极简展示——系统须以大字号、高宽容度图标的视觉方式，按单任务线程模式依次呈现当前待办任务，支持一键"开始执行"或"暂缓跳过"操作，刻意避免列表式平铺布局带来的视觉压迫与决策疲劳。
沉浸式专注模式——提供基于番茄工作法变体的倒计时工具。计时期间，界面须进入全屏沉浸状态，屏蔽导航栏与底部标签栏，通过环形进度条、能量槽或呼吸灯效果等可视化动效，将抽象的"时间流逝"概念具象化呈现，缓解ADHD儿童特有的时间盲区焦虑。
正向打卡与代币激励系统——任务完成后须触发全屏成功庆祝动画并即时发放虚拟代币奖励。代币自动累积至可视化进度池，支持兑换由家长预设的心愿礼物清单。

（3）家长端核心功能需求

家长端定位为家庭管理者的"指挥—观测"控制台，核心功能涵盖：
结构化任务创建与智能模板——家长可新建任务记录，设置执行周期（每日/每周指定日/单次）、奖励代币数额以及前置步骤拆解节点。系统应内置常见生活场景任务模板（如"起床仪式""作业准备"）供快速引用。
多维度数据看板——需支持查看儿童的每日任务总体完成率、各任务的累计专注时长趋势、平均超时偏差比例等行为指标。数据须以柱状图、环形图等直观图表形式呈现。
AI生成的智能反馈——接收由后端大语言模型基于阶段性行为数据自动生成的、以安抚情绪与肯定微小进步为导向的"每日寄语"，并支持家长一键发送至儿童端展示。

（4）管理后台核心功能需求

管理后台面向平台运营人员与超级管理员，核心保障系统的生态健康运转：
用户与组织管理——实现对家长注册账号、儿童子账号的状态管理（冻结、解禁），并监控平台日活数据与异常登录行为。
系统配置与素材管理——集中维护全局任务模板库、奖励图标素材与表扬音效资源，方便端侧应用按需拉取。
LLM服务配置与监控——管理外部大语言模型的API密钥配置、监控Token消耗量趋势，并维护在模型服务不可用时的降级兜底话术库。

2.2.3 系统非功能性需求

（1）性能与响应时延要求

核心API响应时延：专注模式结束时涉及状态同步与代币结算的写操作接口，响应时间需控制在200毫秒以内，确保前端奖励动画的流畅衔接。
LLM异步处理：AI寄语生成通常伴随10至30秒的链路延迟，该类功能必须采用异步处理机制（定时任务调度或消息队列），严禁阻塞主请求线程。

（2）安全性与隐私保护要求

未成年人数据安全：ADHD属于高度敏感的个人健康隐私范畴。数据库设计须遵循数据最小化采集原则，交互传输层启用HTTPS加密。
角色越权防护：严格依托Sa-Token的RBAC（Role-Based Access Control）模型，不仅在路由网关层设防，更须在核心业务逻辑层实施数据归属校验（如强制验证当前家长账号仅可访问其名下绑定的儿童数据），防范横向与纵向的越权攻击。

（3）可用性与兼容性要求

跨终端一致性：UniApp构建的移动端应用须在主流Android厂商设备上保持布局一致性，自适应沉浸式状态栏与异形屏幕。
弱网环境降级：应用的核心倒计时功能模块须具备完全的本地离线运行能力。在网络恢复后，客户端需以后台静默增量同步策略将离线期间的行为数据回传至服务端。


3 系统总体设计

系统总体设计是衔接需求分析与编码实现的核心桥梁环节。本章将首先从宏观层面阐述系统的逻辑分层架构与前后端分离协同机制；继而在中观层面深入剖析认证鉴权、任务生命周期管理、专注交互及智能反馈等核心业务模块的架构方案；最终将业务实体下沉至数据层，给出标准化、高可扩展性的MySQL关系表与Redis缓存的结构设计。

3.1 总体架构设计

图 3.1 系统总体架构设计图

3.1.1 逻辑分层架构设计

"小步"系统秉持高内聚、低耦合的工程设计准则，采用经典的N层逻辑架构体系（N-Tier Architecture）。为确保各层代码的独立可维护性与模块的自主演进能力，系统自上而下严格划分为四个逻辑层次：

表现层（Presentation Layer）：涵盖面向儿童与家长的移动端应用（smallsteps-app）以及面向运营管理人员的Web后台界面（smallsteps-ui）。该层通过UniApp与Vue 3技术栈实现UI渲染逻辑，专司将用户的触控交互行为转化为符合协议规范的HTTP异步请求，并据后端响应结果驱动组件视图的响应式更新。

业务逻辑层（Business Logic Layer）：基于Spring Boot 3构建于后端服务的核心地带（smallsteps-api）。该层封装了全部业务领域知识，包含任务流转规则引擎、代币结算策略、家长与儿童账号的绑定关系管理等。通过标准化的Controller-Service-Manager三级结构对外提供接口，承载系统最关键的业务推演逻辑，同时负责抵御非法参数与越权请求。

数据访问层（Data Access Layer）：借助MyBatis-Plus ORM框架实现与底层数据引擎的解耦。该层向上为业务逻辑层提供语义化的实体查询接口（如LambdaQueryWrapper条件构造、BaseMapper通用方法），消除了直接操作SQL的硬编码耦合。

基础设施层（Infrastructure Layer）：涵盖MySQL关系型数据库、Redis缓存引擎、定时任务调度器（SnailJob）以及对接外部大语言模型API的网络代理与重试机制等基础设施组件。本层将所有与外部系统交互的技术复杂性内聚封装，为上层提供稳定的基础能力输出。

3.1.2 前后端分离协同机制

在物理部署维度，系统完全遵循前后端分离范式。移动端App（运行于客户端本地环境）与Web管理后台（运行于浏览器环境）均通过广域网络，以标准HTTPS协议承载的RESTful API格式，将业务请求发送至部署于云端的Nginx反向代理网关。

Nginx作为系统对外暴露的唯一流量入口，承担负载均衡与跨域请求过滤等网关职责后，将合法流量转发给隐藏于内网的Spring Boot应用集群。前后端之间的数据报文交换统一约定为application/json格式，并通过公共的泛型响应模型（R<T>）进行封装，每个响应体均携带全局统一的业务状态码（code）与提示信息文本（msg），这一约定极大降低了多端协同开发中的接口联调成本。

3.2 核心业务模块设计

3.2.1 用户认证与多角色鉴权模块设计

系统需服务于"超级管理员、家长、儿童"三类权限差异显著的角色身份，访问安全防线的构建全权依托Sa-Token框架实现。

（1）统一登录认证流程：前端通过账号密码向后端/auth/login接口发起认证请求。后端校验通过后调用StpUtil.login(userId)建立会话，框架自动向Redis写入以satoken:login:token:{tokenValue}为Key的会话上下文，同时在HTTP响应头中下发Token凭据。

（2）多端账号体系隔离：为防止管理后台的管理员Token在移动端App中被误用或恶意挪用，系统利用Sa-Token的多账号体系（StpLogic多例模式）架构，将Admin端与App端的会话命名空间在Redis中严格隔离，实现物理层面的Token域分离。

（3）声明式细粒度权限管控：业务层接口在执行业务逻辑前，须经过Sa-Token全局拦截器的前置校验。开发者通过在Controller方法上注入@SaCheckRole("PARENT")或@SaCheckPermission("task:create")等声明式注解，即可实现方法级别的精准鉴权。例如：儿童角色不可调用任务创建与删除接口；家长账号不可跨家庭组织边界查询非关联儿童的数据。

3.2.2 任务生命周期管理与状态机设计

"任务"作为贯穿系统全部功能线的核心领域对象，其生命周期管理采用了具有高弹性的有限状态机（Finite State Machine）模型设计，以适应ADHD患儿行为执行结果高度不确定性的特点。

（1）核心状态枚举：定义了四种互斥的生命周期状态——"待办"（PENDING，任务已分配但尚未开始执行）、"进行中"（IN_PROGRESS，儿童已在该任务内启动专注模式）、"已完成"（COMPLETED，已提交打卡并通过结算）、以及"已过期"（EXPIRED，当日最终未完成自动作废）。

（2）任务配置模型：在家长创建阶段，除标准的标题与预期耗时外，引入了"执行周期类型"（单次/每日循环/自定义频率）与"完成奖励代币权值"两项核心属性。这使得单一任务定义可派生出多条具体日期的待办记录实例。

（3）层级化任务拆解：支持为复杂任务绑定"关联子步骤清单"（parent_id自关联设计），实现无限层级的任务分解结构。这一设计直接回应了ADHD儿童面对大体量任务时产生畏难情绪的核心认知痛点，将系统的支撑能力从"任务提醒"提升至"任务拆解引导"的层次。

3.2.3 专注模式与时间管理交互机制设计

专注模块服务于儿童进入指定任务后的沉浸式时间管理体验。该模块的设计优先级明确为"实时流畅度第一"，其运行期间不涉及持久层的同步写入操作。

（1）启动阶段：前端获取当前选定任务的配置参数（预计时长等），儿童确认开始后，Pinia状态树切入"专注锁定态"。此状态下，App全局路由导航守卫（beforeEach）阻断所有页面跳转请求，底部TabBar组件被条件渲染隐藏，实现全屏沉浸免干扰模式。

（2）自然完成路径：倒计时引擎（基于setInterval与Vue 3响应式ref绑定）计满后，前端封装一个包含{taskId, actualDurationSec, deviceType}的完成记录数据包，发送至后端API。后端在Spring事务管理下（@Transactional）确认任务状态扭转并触发代币奖励结算业务。

（3）中途放弃路径：若儿童主动触发退出（物理返回键或手势），前端弹出二次确认弹窗（防误触设计）。确认放弃后，仍会将本次"有效累积时长"回传后端，后端将其归档并标记为"非完整态完成记录"，作为后续AI模块研判儿童注意力耐受阈值与情绪波动趋势的数据输入。

3.2.4 智能数据反馈与LLM辅助生成模块设计

为了打破传统行为干预中"家长撰写辅导话术枯燥化"以及"干预过程机械化"的困局，系统设计了由后端定时任务驱动、连接外部AI服务的旁路智能反馈闭环。该模块不阻塞日常事务主流程，其运转逻辑如下：

（1）数据聚合阶段：后端定时调度器在每日凌晨特定时段触发，针对每一对"儿童-监护人"绑定关系，聚合该儿童近十日的行为数据快照（任务完成总数、成功率趋势、超时行为频次、情绪打分均值）。

（2）Prompt构建阶段：将聚合后的行为指标格式化为结构化JSON摘要，动态拼接管理后台预配置的系统Prompt模板（如"请依据该儿童近期注意力耐受度的下降趋势，拟定一段家长用陪伴话术，强调同理心与具体行动建议"）。

（3）远程推理阶段：通过Spring WebClient向外部LLM引擎发起异步HTTP请求。由于远程AI调用存在限流与超时风险，系统配置了熔断与降级策略——若连续三次调用失败，自动从本地数据库随机提取一组预设的通用安抚文本作为降级输出。

（4）结果落库与推送：将生成的话术文本脱敏后落库至专用表。待家长次日登录App时，首页专栏模块曝光这一AI分析产出的"辅助指引卡片"，家长可选择一键同步推送至儿童端的"时光信箱"界面展示。

系统的稳定运转依赖于可靠的底层数据持久化支撑。本节梳理支撑上述业务模块落地的核心库表设计与缓存结构规划。

3.3.1 概念模型设计 (E-R图)

通过对业务需求描述中的实体对象与关联关系进行系统化抽取，构建了如下E-R（Entity-Relationship）概念模型：

（1）用户实体（User）：代表系统中的自然人用户，与"角色"构成M:N（多对多）映射。家长与儿童共用同一用户表，通过专用的关系映射表标识监护人-被监护人的绑定关系。

（2）任务定义实体（Task）：与用户表（创建者维度）构成1:N（一对多）关联，记录任务的抽象配置规则（标题、周期、奖励等）。

（3）任务执行日志实体（Task Log）：记录儿童每次按计划执行任务的具象化结果数据。与儿童用户构成1:N关联，与特定日期的特定任务构成1:1关联。

（4）代币流水实体（Reward Log）：详细记载虚拟代币资产的变更历史（来源、数额、时间戳），与用户账户余额属性形成闭环校验关系。

3.3.3 Redis缓存结构设计

系统中存在多个高频读写场景（如移动端每次路由跳转触发的会话合法性校验、首页数据看板的积分排名查询等），若直接由MySQL承载将迅速击穿性能指标。因此引入Redis构建了全局分布式缓存层：

（1）会话认证缓存：配合Sa-Token框架，按用户维度建立形如satoken:login:session:{userId}的Hash对象，存储权限集合（Permission Sets）与会话过期时间戳，消除了每次权限比对操作的数据库查询开销。

（2）防并发重复提交锁：利用Redis Key的TTL（Time-To-Live）自动过期机制，结合SETNX（Set if Not Exists）原生原子指令实现分布式互斥锁。当儿童端快速双击"任务完成"按钮时，第二次请求将被锁机制拦截，从根本上杜绝了因网络延迟导致重复结算并超额发放代币的并发安全风险。

（3）行为数据预聚合缓存：每日凌晨的定时聚合任务产出的统计摘要JSON，以child:{childId}:dashboard:summary为Key缓存至Redis，设置24小时过期。家长端请求数据看板时优先命中缓存，显著降低了后端数据库的聚合查询压力。

4.1 后端服务实现 (smallsteps-api)

后端服务项目的工程结构遵循Spring Boot社区推荐的多模块分层约定。顶层的smallsteps-api聚合模块统一管理Maven依赖版本与插件配置；核心业务代码按照领域边界拆分为Controller（控制器层）、Service/Impl（业务逻辑层）、Mapper（数据访问层）以及Domain（领域实体层）四个逻辑包。跨切面的基础设施能力（如全局异常处理、请求日志AOP、跨域配置）则收敛至独立的Framework模块。

4.1.1 安全认证与路由拦截实现

安全认证模块是整个后端服务的第一道防线，其实现基于Sa-Token框架提供的拦截器引擎与注解式鉴权能力。

在系统启动阶段，通过实现WebMvcConfigurer接口的addInterceptors方法，将SaInterceptor注册为全局HTTP请求拦截器。该拦截器在每一次请求到达Controller方法前自动触发Token有效性校验——从请求头中的Authorization字段提取Token字符串，查询Redis中对应的会话上下文，验证其是否处于有效期内且未被其他设备登录踢出。对于白名单中的公开路径（如/auth/login、/captcha/get），通过SaRouter.match().free()声明免检放行。

多角色鉴权逻辑的实现则充分利用了Sa-Token的声明式注解。以任务创建接口为例：在SsTaskController的create方法上标注@SaCheckRole("PARENT")注解，框架在方法执行前自动从当前会话中提取用户角色标记并与注解声明值进行比对。若当前登录用户为儿童角色，校验不通过时将直接抛出NotRoleException，由全局异常处理器统一包装为标准错误响应返回前端。这种声明式的鉴权方式将安全逻辑从业务代码中完全剥离，保障了Controller方法的职责单一性。

在数据层面的越权防护中，Service层的实现代码内嵌了"数据归属强校验"逻辑。以家长查询其名下儿童的任务列表为例，核心查询逻辑伪代码如下：

// 获取当前登录家长的userId
Long parentId = StpUtil.getLoginIdAsLong();
// 查询亲子绑定关系表，获取该家长关联的所有childId
List<Long> childIds = parentChildMapper.selectChildIdsByParentId(parentId);
// 构建带有强制in约束的查询条件
LambdaQueryWrapper<SsTaskLog> wrapper = new LambdaQueryWrapper<>();
wrapper.in(SsTaskLog::getChildId, childIds);

上述逻辑确保即便攻击者篡改了请求参数中的childId，查询结果也只会返回当前家长实际绑定的儿童数据，从SQL层面杜绝了横向越权的可能性。

4.1.2 任务管理核心业务逻辑实现

任务管理模块承担了从"家长创建任务"到"儿童完成打卡"全链路的业务编排职责。以任务的"完成打卡"操作为核心场景，阐述其事务性业务逻辑的实现要点：

当儿童端发起任务完成请求时，后端SsTaskService的completeTask方法在@Transactional注解标记的事务边界内依次执行以下步骤：

第一步，幂等性校验：通过Redis分布式锁（Lock4j的@Lock4j注解），对请求中携带的taskLogId施加防重复提交锁。锁的Key格式为lock:task:complete:{taskLogId}，过期时间设定为10秒。若同一taskLogId的第二个请求在锁存续期内到达，将被框架直接拒绝并返回"请勿重复提交"的业务提示。

第二步，状态合法性校验：从数据库读取该taskLogId对应的任务执行日志记录，断言其当前状态必须为"进行中"（IN_PROGRESS）。若状态不匹配（如已被标记为"已完成"或"已过期"），抛出业务异常终止事务。

第三步，日志状态扭转：将任务执行日志的status字段更新为"已完成"（COMPLETED），同步写入实际专注时长（actualDuration）与完成时间戳（endTime）。

第四步，代币奖励结算：查询关联的任务定义表获取该任务配置的奖励代币数额（rewardAmount），通过SQL原子操作UPDATE sys_user SET coin_balance = coin_balance + #{amount} WHERE user_id = #{childId}更新儿童的代币账户余额，并同步向代币流水表（ss_reward_log）插入一条收入类型的变更记录。

第五步，进度更新：若该任务属于某父级任务的子步骤，系统将重新计算父任务下所有子步骤的完成比例，并同步更新父任务的完成进度百分比。当所有子步骤均达成完成态时，父任务自动流转至"已完成"状态。

4.1.3 数据看板聚合与智能生成服务实现

数据看板模块为家长端与管理后台提供多维度的儿童行为统计数据接口。其实现采用"定时预计算 + 缓存命中"的异步架构模式，避免前端每次请求实时触发复杂的聚合查询。

在后端，一个由SnailJob定时任务调度框架驱动的聚合Job在每日凌晨02:00触发执行。该Job遍历所有活跃状态的儿童用户ID，针对每一位儿童执行以下聚合逻辑：

（1）统计近7天每日的任务完成数量与成功率百分比；
（2）计算近7天每日的累计专注时长与平均单次专注时长；
（3）读取情绪记录表中最近7日的情绪评分序列，计算趋势变化率。

聚合产出的结构化JSON摘要被写入Redis缓存（Key格式：child:{childId}:dashboard:summary，TTL设定为24小时），同时落库至持久化统计表作为历史归档。家长端请求数据看板API时，Service层优先执行Redis GET操作，命中缓存则直接返回，未命中时方才回源至数据库执行实时查询并回填缓存。

在智能寄语生成环节，聚合Job的下游衔接了一个LLM调用子任务。该子任务将行为摘要JSON拼接预设Prompt模板后，通过Spring WebClient非阻塞客户端向配置的AI模型服务端点发起HTTP POST请求。为确保LLM服务的不可用不影响系统主体功能的稳定性，实现代码采用了如下降级策略：

// 伪代码：LLM调用与降级
try {
    String aiResponse = webClient.post()
        .uri(llmApiEndpoint)
        .bodyValue(promptPayload)
        .retrieve()
        .bodyToMono(String.class)
        .timeout(Duration.ofSeconds(30))
        .block();
    // 落库AI生成结果
    saveLlmMessage(childId, aiResponse);
} catch (Exception e) {
    log.warn("LLM服务调用失败，启用降级兜底", e);
    // 从本地预配置话术库随机选取
    String fallback = fallbackMessageService.getRandomMessage();
    saveLlmMessage(childId, fallback);
}

4.2.1 项目工程化配置与Vue 3生态集成

项目使用Vite作为构建工具链，对比Webpack具备显著优势的热模块替换（HMR）速度与冷启动性能。核心依赖配置如下：

运行时框架：vue@3.5.30 + @dcloudio/uni-app@3.0

4.2.2 基于Pinia的双模式状态管理设计

"小步"App的独特需求在于同一应用内需承载"家长模式"与"儿童模式"两套完全不同的视图逻辑与数据流程。系统通过Pinia Store的模块化设计实现了这一架构挑战。

在用户Store（useUserStore）中，维护了一个currentMode响应式状态变量，其取值为'PARENT'或'CHILD'。登录成功后，Store根据后端返回的userType字段自动初始化该模式标记。核心设计要点在于：App的底部导航栏TabBar配置、首页组件的条件渲染以及路由导航守卫的放行逻辑，均通过computed计算属性响应式地绑定至currentMode值——当模式切换时，整个UI骨架与可访问路由表自动同步更新，无需手动清理或重建组件状态。

以首页为例，家长模式下渲染的是"今日待办概览 + 数据迷你看板 + AI寄语卡片"的管理型布局，而儿童模式下渲染的是"当前任务大卡片 + 代币余额展示 + 成就徽章墙"的游戏化布局。两套布局通过Vue 3的<component :is="currentModeView" />动态组件机制挂载，共享底层数据但呈现完全不同的视觉与交互逻辑。

4.2.3 TailwindCSS驱动的认知减负界面构建

面向ADHD儿童用户群体的界面构建，是本系统在前端工程层面最具设计挑战性的实践环节。

在色彩体系层面，项目的tailwind.config.js中自定义了一套面向ADHD群体的"低刺激色板"，以低饱和度、中明度为基调：主色调采用柔和蓝绿色系（#6EC6CA），而非通常效率App使用的高饱和度红色或橙色，旨在从色彩心理学层面营造安宁与专注的情绪氛围；成功反馈色选用暖金色（#F4D35E）替代刺激性绿色，以奖章质感传达成就认同；错误提示刻意回避了警告性红色，改用偏柔和的浅珊瑚色（#F08080），将"错误"感知转化为"需要关注"的温和提示。

在布局策略层面，儿童端页面严格遵循"单列信息流"原则——每一屏仅展示一个核心信息块。任务卡片采用圆角（rounded-2xl, 即16px border-radius）与轻柔阴影（shadow-md）的视觉语法，模拟"纸质便签"的物理隐喻，降低数字界面的冰冷感与距离感。关键操作按钮使用大触控热区设计（min-height: 48px, padding: 16px 32px），确保即便是在精细动作控制能力较弱的ADHD儿童操作下也不易误触。

4.2.4 核心交互流实现：任务卡片与番茄钟

任务卡片组件（TaskCard.vue）作为儿童端出现频率最高的交互元素，其实现逻辑凝结了"认知卸载"理念的多项工程化转化。组件接收一个task Prop对象，内部通过computed属性衍生出简化的显示文案（超过10字自动截断并拼接省略号）、对应分类的Icon引用以及基于任务优先级的卡片边框色。卡片主体采用flex布局，左侧为任务分类图标（64x64像素视觉锚点），右侧为标题与预计时长文案，整体呈"一眼可读"的信息密度。

番茄钟页面（FocusTimer.vue）是App中认知聚焦度最高的全屏沉浸组件。其核心实现要点包括：

（1）全屏沉浸态控制：组件挂载（onMounted）时，调用uni.hideTabBar()隐藏底部导航，并通过Pinia全局状态isFocusMode = true通知路由守卫锁定导航。组件卸载（onUnmounted）时恢复。

（2）环形进度条渲染：使用Canvas 2D API在页面中心绘制一个半径120像素的环形进度弧线。进度百分比通过计算属性(elapsedTime / totalTime * 100)响应式绑定，随倒计时引擎每秒更新一次弧线角度，实现平滑的视觉时间流逝反馈。环形颜色分为三段渐变：起始段为柔和蓝色，中段过渡为蓝绿色，末尾10%切入温暖金色，暗示"即将达成"的成就激励信号。

（3）任务完成庆祝动效：倒计时结束瞬间，触发一组精心编排的多层动画序列——背景层的五彩纸屑粒子散落效果（基于CSS @keyframes与随机transform参数生成）、中间层的成就星星放大弹出动画、以及前景层的"+N代币"数字飞入效果。该动画序列总时长控制在2.5秒，在提供充分的正向即时奖励刺激的同时，避免过长的动效时间分散儿童对后续任务的关注准备。

4.3 Web管理后台实现 (smallsteps-ui)

管理后台面向平台运营人员与超级管理员，基于Vue 3.5 + Element Plus 2.11组件库构建标准化的单页应用（SPA）。

4.3.2 数据可视化看板与列表渲染

管理后台的数据可视化分析页面通过集成ECharts 5.6图表引擎实现对全平台行为数据的宏观洞察。

核心看板页面的数据面板包含以下可视化模块：

（2）任务完成率分布饼图：以环形饼图（doughnut chart）呈现当前周期内全平台任务的"已完成/进行中/已过期"比例分布，中心区域叠加显示总体完成率百分比数字。

（3）高频任务类型排行柱状图：以水平柱状图（barChart, horizontal orientation）展示被家长创建频次最高的任务类别（如"作业监督""洗漱流程""睡前阅读"），为运营人员优化预置任务模板库提供数据依据。

6 总结与展望

6.1 全文工作回顾

本课题以ADHD中小学生群体在日常行为管理领域面临的现实困境为研究起点，在深入调研传统干预手段的局限性与现有数字化辅助工具适配缺口的基础上，运用软件工程的系统化方法论，完成了"小步（Small Steps）"行为习惯辅助系统从需求分析、架构设计到工程实现与测试验证的完整研发流程。

在系统分析阶段，本文从ADHD患儿的认知加工特征与家长群体的管理痛点两个维度出发，构建了"双核用户画像"，并据此推导出儿童端、家长端与管理后台三个子系统的功能性需求规格与非功能性质量属性要求，为后续阶段的设计决策提供了清晰的业务锚点。

在系统设计阶段，本文采用N层逻辑架构与前后端分离范式，设计了以Spring Boot 3为核心后端引擎、UniApp + Vue 3为移动端呈现层、Vue 3 + Element Plus为管理后台呈现层的技术架构体系。核心业务模块层面，重点阐述了基于Sa-Token的多角色细粒度鉴权方案、任务生命周期有限状态机模型、专注模式的前端沉浸态控制机制以及融合LLM能力的异步智能反馈生成闭环。数据层面，依据E-R概念模型完成了MySQL核心表结构设计与Redis多场景缓存策略规划。

在系统实现阶段，本文分别从后端业务逻辑（安全认证拦截、事务性任务结算、AI调用降级）、移动端前端工程（Pinia双模式状态管理、TailwindCSS认知减负界面、Canvas环形番茄钟）以及管理后台（动态权限路由、ECharts数据看板、VXE-Table高性能列表）三个维度展示了关键技术方案的落地实践。

在系统测试阶段，通过覆盖权限隔离、任务全链路流转以及专注模式异常交互等多维度的测试用例执行与结果分析，验证了系统在功能正确性、安全防护有效性以及交互容错能力方面均达到了设计阶段制定的目标基准。

6.2 系统设计中的关键技术挑战与解决思路

在整个系统的设计与实现过程中，以下几项技术挑战最为突出，其探索与解决过程具有一定的工程参考价值：

（1）认知心理学理论到前端UI组件的工程化映射：将"降低外在认知负荷"这一抽象理论命题转化为可量化的设计指标（如每屏信息元素数量上限、色彩饱和度阈值、触控热区最小面积等），并在TailwindCSS原子化样式系统中固化为可复用的设计Token，是跨学科设计类课题中极具挑战性的实践环节。本系统通过在tailwind.config.js中建立自定义色板与间距规则的方式实现了这一转化，确保了全端界面视觉语言的一致性。

（2）LLM外部服务的可靠性治理：大语言模型服务作为当前技术生态中固有不稳定的外部依赖，其响应延迟与可用性波动对系统主体功能构成潜在威胁。本系统通过将LLM调用从主请求链路中完全剥离至定时任务异步旁路、配合本地降级话术库的"双保险"策略，实现了"AI增强但非AI依赖"的稳健架构目标。

（3）多角色共存系统中的数据安全边界管控：同一数据库中存储着管理员、家长与儿童三类角色的敏感数据。本系统在接口鉴权（Sa-Token注解）与数据层（SQL强制归属校验）两个层面构建了纵深防御体系，有效实现了即便Token被盗用也无法突破数据归属边界的安全目标。

6.3 现有不足与未来研究方向

尽管系统在核心功能层面已经实现了所有设计阶段制定的目标，但在以下领域仍存在可优化的空间，也构成了后续研究的方向：

（1）辅助效果的循证评估缺位：受限于课题周期与伦理审查流程，本系统尚未能在真实的ADHD临床样本群体中开展对照实验，以量化验证数字辅助对行为习惯改善的实际效果量（Effect Size）。后续研究应与专业医疗机构合作，设计随机对照试验（RCT）方案，收集使用前后的标准化行为量表评分数据（如Conners评定量表），为系统的干预效果提供循证医学级别的证据支撑。

（2）个性化智能推荐算法的深化：当前系统的LLM辅助寄语生成依赖于基于规则的Prompt模板组装，智能化程度有限。未来可引入基于儿童历史行为数据的机器学习用户画像模型，实现任务推荐、奖励权重以及提示强度等参数的全面自适应个性化调优，进一步提升干预的精准度。

（3）社交化与同伴激励维度的扩展：当前系统的激励设计以个体维度的代币积分为主。参照发展心理学关于同伴影响力的研究成果，未来可探索匿名化的"同龄伙伴群组挑战"功能——让ADHD儿童在保护隐私的前提下感受到"还有和我一样在努力的小伙伴"的群体支持，有望从社会认知维度引入额外的正向激励增量。

（4）无障碍访问（Accessibility）的进一步增强：当前界面设计虽已充分考虑了ADHD群体的认知特征，但在视力障碍、听力障碍等合并障碍（Comorbidity）人群的适配上仍存在盲区。后续开发应严格对标WCAG 2.1 AA级标准，补充屏幕阅读器语义标注、键盘焦点管理以及高对比度模式等无障碍访问特性。
