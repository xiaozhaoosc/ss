## 问题一：孩子档案数据库有 2 个，页面显示 4 个

### 1.1 现象描述

家长中心的孩子档案列表显示了 4 条记录，但用户认为数据库中只有 2 个孩子。

### 1.2 根因分析

**根因：`ss_child` 表中存在重复数据，实际有 5 条记录（同一 `parent_id` 下有 4 条）。**

#### 数据来源追踪

数据库 dump (`ss_20260527.sql` L229-233) 显示，`ss_child` 表实际有 **5 条记录**：

| id | parent_id | nickname | tenant_id | 备注 |
|---|---|---|---|---|
| 1002 | 2035392423676469250 | 小明 | SS0001 | 原始数据，有完整字段（avatar_config、daily_config、challenges、birthday 等） |
| 1003 | 2035392423676469250 | 小红 | SS0001 | 原始数据，有完整字段 |
| **10001** | **2035392423676469250** | **小明** | **SS0001** | ⚠️ 重复！`test_data_smallsteps.sql` 插入，多数字段为 NULL |
| **10002** | **2035392423676469250** | **小红** | **SS0001** | ⚠️ 重复！`test_data_smallsteps.sql` 插入，多数字段为 NULL |
| 2047877554018242562 | 200 | test12 | 000000 | 测试账号，属于另一个家长 |

#### 重复数据产生原因

1. **原始初始化**: `init_smallsteps.sql` 或早期脚本创建了 id=1002（小明）和 id=1003（小红），`parent_id = 2035392423676469250`
2. **测试数据脚本**: `test_data_smallsteps.sql` (L203-258) 又插入了 id=10001（小明）和 id=10002（小红），`parent_id` 被设为 `1000`
3. **后续更新**: 某次操作将 10001/10002 的 `parent_id` 也改成了 `2035392423676469250`（或者用的就是 `ON CONFLICT DO UPDATE`）

#### 查询链路确认

```
[前端] profile/index.vue
  └─ listChildren({ parentId: userId })
      └─ GET /ss/child/list?parentId=<userId>
          └─ ChildController.list(Child child)
              └─ ChildServiceImpl.selectChildList(child)  ← L32-37
                  └─ SELECT * FROM ss_child WHERE parent_id = #{parentId}
```

- 前端代码: [`profile/index.vue`](file:///home/ken4zhao/Documents/office/jushuang1/github/ss/smallsteps-app/src/pages/parent/profile/index.vue#L159-L175) — **纯 API 获取，无 mock 数据**
- API 定义: [`child.ts`](file:///home/ken4zhao/Documents/office/jushuang1/github/ss/smallsteps-app/src/api/child.ts#L240-L246) — 调用 `GET /ss/child/list`
- Service 层: [`ChildServiceImpl.java`](file:///home/ken4zhao/Documents/office/jushuang1/github/ss/smallsteps-api/smallsteps-modules/smallsteps-child/src/main/java/com/kenzhao/smallsteps/child/service/impl/ChildServiceImpl.java#L32-L37) — 按 `parent_id` 查询，无去重逻辑

### 1.3 修复方案

#### 方案 A：清理重复数据（推荐 ✅）

```sql
-- 删除测试脚本产生的重复记录，保留原始的完整数据 (id=1002, 1003)
DELETE FROM ss_child WHERE id IN (10001, 10002);
```

**理由**：id=1002/1003 的数据更完整（有 `avatar_config`、`daily_config`、`challenges`、`birthday` 等字段），id=10001/10002 的这些字段全部为 NULL。

#### 方案 B：加唯一约束防止未来重复

```sql
-- 在 parent_id + nickname 上添加唯一约束（可选）
-- 注意：同一家庭的不同孩子可能有相同昵称，需谨慎评估
ALTER TABLE ss_child ADD CONSTRAINT uk_parent_nickname 
  UNIQUE (parent_id, nickname) WHERE del_flag = '0';
```

#### 方案 C：修复测试数据脚本

在 `test_data_smallsteps.sql` 中将 id=10001/10002 的 `parent_id` 改为与 init 脚本一致（`2035392423676469250`），并确保使用 `ON CONFLICT (id) DO UPDATE` 避免重复。

## 问题二：绑定新档案失败 — "修改用户null信息失败"

### 2.1 现象描述

在家长中心 → 关联新档案页面，输入 `child_roy` 后点击绑定，`POST /parent/family/bind-child` 返回：

```json
{
    "code": 500,
    "msg": "修改用户null信息失败",
    "data": null
}
```

### 2.2 调用链分析

```
POST /parent/family/bind-child  { "userName": "child_roy" }
  └─ ParentFamilyController.bindChild(ChildBindDTO{userName="child_roy"})
      ├─ LoginHelper.getDeptId()  → 获取当前家长的 deptId
      ├─ userService.selectUserByUserName("child_roy")  → 查到 SysUserVo
      └─ userService.updateUser(SysUserBo{userId=xxx, deptId=yyy})  ← ⚠️ 这里出问题
          ├─ insertUserRole(user, true)   → roleIds=null → 直接 return（无影响）
          ├─ insertUserPost(user, true)   → postIds=null → 直接 return（无影响）
          ├─ MapstructUtils.convert(SysUserBo → SysUser)  → ⚠️ 只有 userId+deptId，其他全 null
          └─ baseMapper.updateById(sysUser)  → ⚠️ 返回 0 行 → 抛异常
              ↓ 异常信息
              "修改用户" + user.getUserName() + "信息失败"
                            ↑ userName=null（因为 SysUserBo 中未设置 userName）
              = "修改用户null信息失败"
```

### 2.3 根因定位

**核心代码**: [`ParentFamilyController.java`](file:///home/ken4zhao/Documents/office/jushuang1/github/ss/smallsteps-api/smallsteps-modules/smallsteps-parent/src/main/java/com/kenzhao/smallsteps/parent/controller/ParentFamilyController.java#L60-L77)

```java
SysUserBo updateChild = new SysUserBo();
updateChild.setUserId(child.getUserId());
updateChild.setDeptId(deptId);
return toAjax(userService.updateUser(updateChild));  // ← 问题出在这里
```

**问题分解**：

1. **`SysUserBo` 只设了 `userId` 和 `deptId`**，其他字段全是 `null`（包括 `userName`）
2. `updateUser()` 调用 `MapstructUtils.convert(SysUserBo → SysUser)` 转换后，得到一个几乎全空的 `SysUser` 对象
3. `baseMapper.updateById(sysUser)` 是 MyBatis-Plus 的方法，**默认 `null` 字段不会被更新**（`FieldStrategy.NOT_NULL`），所以只会生成 `UPDATE sys_user SET dept_id=? WHERE user_id=?`
4. **但是**，`updateById` 被 `@DataPermission` 注解修饰（[SysUserMapper.java L125-129](file:///home/ken4zhao/Documents/office/jushuang1/github/ss/smallsteps-api/smallsteps-modules/smallsteps-system/src/main/java/com/kenzhao/smallsteps/system/mapper/SysUserMapper.java#L124-L129)），会在 WHERE 条件中追加数据权限过滤：

```sql
UPDATE sys_user 
SET dept_id = ? 
WHERE user_id = ? 
  AND dept_id IN (当前用户有权访问的部门)  -- @DataPermission 追加
```

5. **当家长用户的数据权限不包含目标儿童所在部门时，WHERE 条件匹配 0 行**
6. `updateById` 返回 `0`，触发 [`SysUserServiceImpl.java L406-408`](file:///home/ken4zhao/Documents/office/jushuang1/github/ss/smallsteps-api/smallsteps-modules/smallsteps-system/src/main/java/com/kenzhao/smallsteps/system/service/impl/SysUserServiceImpl.java#L405-L408)：

```java
if (flag < 1) {
    throw new ServiceException("修改用户{}信息失败", user.getUserName());
    //                                              ↑ null → 显示 "null"
}
```

### 2.4 问题本质

**两层问题叠加**：

| 层级 | 问题 | 严重程度 |
|---|---|---|
| **架构设计** | `bindChild` 不应调用通用的 `updateUser()`（带数据权限、角色/岗位处理的重量级方法），只是为了改一个 `dept_id` 字段 | 🔴 高 |
| **数据权限** | 家长角色的数据权限范围可能不覆盖目标儿童用户，导致 `@DataPermission` 过滤后 WHERE 匹配 0 行 | 🔴 高 |
| **错误信息** | `SysUserBo` 未设 `userName`，异常消息中拼接出 `null` | 🟡 中 |
| **副作用风险** | 若 `roleIds`/`postIds` 不为空，`insertUserRole(user, true)` 会先 DELETE 再 INSERT，可能清掉儿童已有的角色 | 🟠 潜在 |

### 2.5 修复方案

#### 方案 A：绕过 `updateUser`，直接更新 `dept_id`（推荐 ✅）

修改 [`ParentFamilyController.bindChild()`](file:///home/ken4zhao/Documents/office/jushuang1/github/ss/smallsteps-api/smallsteps-modules/smallsteps-parent/src/main/java/com/kenzhao/smallsteps/parent/controller/ParentFamilyController.java#L58-L77)，不再调用重量级的 `updateUser()`，改为直接更新 `dept_id` 字段：

**方式 1**: 在 `ISysUserService` 中新增轻量方法

```java
// ISysUserService 新增
int updateUserDeptId(Long userId, Long deptId);

// SysUserServiceImpl 实现 — 不带 @DataPermission
@Override
public int updateUserDeptId(Long userId, Long deptId) {
    return baseMapper.update(null,
        new LambdaUpdateWrapper<SysUser>()
            .set(SysUser::getDeptId, deptId)
            .eq(SysUser::getUserId, userId));
}
```

**方式 2**: 在 Controller 中使用 `updateUserDeptId`

```java
@PostMapping("/bind-child")
public R<Void> bindChild(@RequestBody ChildBindDTO bindDTO) {
    Long deptId = LoginHelper.getDeptId();
    if (deptId == null) {
        return R.fail("家长尚未归属任何家庭，请先联系管理员创建家庭。");
    }

    SysUserVo child = userService.selectUserByUserName(bindDTO.getUserName());
    if (child == null) {
        return R.fail("未找到该儿童账号");
    }

    // 直接更新 dept_id，绕过数据权限和角色/岗位处理
    int rows = userService.updateUserDeptId(child.getUserId(), deptId);
    if (rows < 1) {
        return R.fail("绑定失败，请稍后重试");
    }
    return R.ok();
}
```

#### 方案 B：给家长角色配置足够的数据权限

在 `sys_role` 表中，确保家长角色（如 `role_key = 'parent'`）的 `data_scope` 设置为 `DATA_SCOPE_ALL` 或包含所有部门。

> ⚠️ **不推荐**：这会扩大家长的数据访问范围，违反最小权限原则。
