# ADHD 模板库 App 端展示与交互设计 (Design Spec)

## 1. 目标与背景 (Context & Goals)
当前针对 `smallsteps-ai` 的任务拆解稳定性压测已完成，并且“ADHD 模板库”已具备实战能力。本设计的目的是在 `smallsteps-app` (基于 UniApp + Vue 3) 移动端应用中，模拟展示这些模板库的最佳视觉效果和操作流程。

## 2. 核心决策 (Decisions)
在头脑风暴和视觉展示中达成以下决策共识：

1.  **展示风格**: 采用 **卡片网格流 (Card Grid)**。
    *   **理由**: 类似 Pinterest 的大图标与颜色区分，能够带来强烈的视觉冲击力，非常适合 ADHD 人士或创意工作者进行无压力的探索和发现。
2.  **数据流**: 对接 **真实的后台数据**。
    *   **理由**: 页面需要拉取压测生成的实际模板数据，完成真实的应用操作流（应用模板到今日任务），而不是仅做静态 UI 模拟。
3.  **交互流**: 采用 **全屏详情页 (Full Screen Detail)**。
    *   **理由**: 点击模板卡片后跳转至新页面，能够提供充足的展示空间，让用户沉浸式地浏览完整的模板步骤。底部提供固定的“应用此模板”大按钮。
4.  **其余未尽细节**: 默认选择最直接、沉浸感最强的主流方案（预设选项 A）。

## 3. 架构与组件拆解 (Architecture & Components)

### 3.1 路由与页面规划
*   **列表页 (`pages/template/library.vue`)**:
    *   负责展示所有的可用模板。
    *   支持下拉刷新获取最新模板数据，支持上拉加载更多。
    *   使用两列网格布局，展示模板标题、标签、卡片背景色/图标、步骤数量等摘要信息。
*   **详情页 (`pages/template/detail.vue`)**:
    *   接收由列表页传递的模板 `id`。
    *   页面顶部区域展示模板的主题视觉（大图或主题色块）。
    *   中部区域使用时间轴或步骤列表的方式展示各项子任务细节。
    *   底部悬浮固定按钮：“应用此模板”，点击后执行业务逻辑。

### 3.2 独立组件设计
*   **卡片组件 (`src/components/TemplateCard.vue`)**:
    *   将模板摘要卡片封装为独立组件，以便后续在 App 首页推荐区或其他入口复用。
    *   入参：模板对象数据（`title`, `color`, `tags`, `stepCount` 等）。

### 3.3 数据层与 API 封装
需要在 `src/api/template.js` 中新增以下接口封装：
1.  `getTemplateList(params)`: 获取模板列表。
2.  `getTemplateDetail(id)`: 获取单个模板详情步骤。
3.  `applyTemplate(id, targetDate)`: 确认应用当前模板，将其子任务添加到指定的日期日程中。

## 4. 错误处理与边缘情况 (Error Handling)
*   **网络或接口异常**: 若 `getTemplateList` 失败，展示默认的网络异常占位图与重试按钮。
*   **空数据**: 若当前分类下暂无模板，显示友好的空状态（Empty State）插画。
*   **应用失败**: 若点击“应用”接口返回错误，通过 `uni.showToast` 提供明确的文本提示（例如“添加失败，请稍后重试”）。

## 5. 测试策略 (Testing Strategy)
*   **UI 测试**: 使用 Playwright (如 package.json 所示配置) 进行 E2E 视图验证，确保卡片网格布局在不同分辨率下的兼容性。
*   **集成测试**: 模拟真实的接口调用链路，确保从点击卡片 -> 进入详情页 -> 点击应用按钮后的状态流转正确无误。
