# Journal: 2026-04-08

## [Project_Awaken]
- **今日目标**：修复 App 端角色权限分流，完善登录 UI 的动态配置逻辑，以及更新核心数据库模型。
- **状态现状**：App 端存在角色混淆（儿童登录后误入家长界面），验证码配置未与后端同步。

## Milestone Items (关键成果)

### 1. 角色分流逻辑加固
- **现象**：儿童账号登录后加载了默认的家长 TabBar。
- **定位**：`userStore` 的数据解包路径错误，未指向 `res.data`；判定条件过窄，未关联 `user_type`。
- **修复**：重写了 `getUserInfo` 与角色判定逻辑，现已支持基于 `user_type` (3) 的精准分流。
- **详细参考**：[[20260408_Role_Routing_Fix]]

### 2. 登录 UI 精简化
- **修改**：移除了 App 与 UI 中硬编码的租户/验证码默认开启状态。
- **逻辑**：现改为 `false` 默认，仅当后端配置返回 `true` 时显现。解决了“禁用后依然显示”的 UX 弊病。

### 3. 数据库全景图更新 (v2.1)
- **改进**：在 `db.md` 中强化了 `ss_reward` (奖励) 与 `sys_dept` (家庭/机构) 的关联模型。
- **新增**：增加了 `ss_parent_child` 关系表模型，支持多对多绑定。
