# 2026-04-14 论文多版本 Word 格式化生成

> **日期**: 2026-04-14  
> **主题**: 毕业论文 Word 文档自动化生成  
> **上下文**: [[_index_wiki]] / [[System-Architecture]]

## 执行摘要

本日核心工作为将论文 Markdown 源稿批量转换为符合上海应用技术大学高等学历继续教育格式规范的 `.docx` 文件。

## 关键决策

### 1. 自动化生成方案选型
- **工具**: `python-docx` 库
- **原因**: 无需安装 Office 环境，可在服务器/CI 中执行；对中文字体、三线表等格式的控制力强
- **替代方案评估**: `pandoc` 对中文学术格式的控制力不足，放弃

### 2. 格式规范对照
| 格式项 | 规范要求 | 实际实现 |
|--------|----------|----------|
| 页面尺寸 | A4 (21×29.7cm) | ✅ |
| 页边距 | 上下2.54cm, 左右3.17cm | ✅ |
| 一级标题 | 黑体三号(16pt)加粗居中 | ✅ |
| 二级标题 | 黑体四号(14pt)加粗 | ✅ |
| 三级标题 | 黑体小四(12pt)加粗 | ✅ |
| 正文 | 宋体小四(12pt), 1.5倍行距, 首行缩进2字符 | ✅ |
| 表格 | 三线表, 宋体五号 | ✅ |
| 参考文献 | 宋体五号 | ✅ |
| 代码块 | Courier New 小五号 | ✅ |

### 3. v2 与 v4 版本差异
| 维度 | v2 | v4 |
|------|-----|-----|
| 数据库 | MySQL 8.0 | Postgres 15 |
| 调度框架 | SnailJob | 后端定时任务 |
| 并发控制 | Lock4j + Redisson | Redis SETNX |
| 前端测试设备 | Xiaomi 14 + Samsung A52 | 华为 P40 Pro + Mate 30 Pro |
| 论文结构 | 详细设计章独立 (ch.4) | 系统实现章 (ch.4) |
| 结论风格 | 技术挑战分析 | 研究意义与贡献 |

## 输出产物
- `v2_上海应用技术大学高等学历继续教育本科计算机专业毕业论文.docx` (55KB)
- `v4_上海应用技术大学高等学历继续教育本科计算机专业毕业论文.docx` (62KB)
- `generate_thesis.py` — v4 生成脚本
- `generate_thesis_v2.py` — v2 生成脚本

## 影子观察 (Shadow Observations)
- 论文 v2 使用 MySQL，v4 已迁移至 Postgres 15 —— 保持版本间技术栈表述一致性很重要
- python-docx 不支持直接生成 `.doc` 格式（仅 `.docx`），若学校严格要求 `.doc` 需用 LibreOffice 转换
- 两版论文的参考文献格式存在细微差异，建议统一为 GB/T 7714 标准
