## 关键突破
### 1. 统一请求链路 (`request.ts`)
- **动作**：废弃 `request.js`，全面转向类型化的 `request.ts`。
- **创新点**：引入了 **“强力正则解析器”**。针对 App 环境中可能出现的 `Status 500 {"code":500...}` 这种复合字符串，使用 `match(/\{[\s\S]*\}/)` 自动提取有效的业务 JSON。
- **UX 优化**：针对业务错误，实现了从 `Toast` 向 `Modal` 的自动降级逻辑。长消息（如 MapStruct 转换异常）不再被截断。

### 2. PostgreSQL 数据库类型迁移 (方案 B)
- **挑战**：后端报错 `不良的类型值 long : \n` 或 `invalid input syntax for type bigint: "admin"`。
- **根源**：`ss_child_ai.create_by` 字段为 `VARCHAR`，但 Java 端强制映射为 `Long`。数据库中混入了 `""`、`"admin"` 等非数字内容。
- **决策**：执行 [[ADR_006_DB_Schema_BigInt_Migration]]。
- **实施**：使用正则表达式 `!~ '^[0-9]+$'` 清洗所有非数字脏数据，并执行 `ALTER TABLE ... TYPE int8`。

## 隐患预警 (DEBT_LEADGER)
