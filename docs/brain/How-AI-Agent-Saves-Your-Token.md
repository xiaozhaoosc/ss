## 1. 什么是 Token？（AI 的“能量金币”）

我们可以把 **Token** 简单理解为 AI 说话、写代码和思考时的“字数”或“能量金币”：
* 你给 AI 发送的每一句话、AI 读进去的每一行代码，叫做 **输入 Token (Input)**。
* AI 给你回复的每一句解释、为你写出的每一行新代码，叫做 **输出 Token (Output)**。

在 AI 的世界里，每一次对话，AI 并不是只看你最新发的那句话，而是需要把你**之前聊过的一大堆历史记录、当前项目的所有代码和背景文档**全部塞进它的脑袋里（这个脑袋的容量叫做**上下文窗口**）。

这就像你每次去超市买菜，如果收银员要求你**必须把这辈子所有的超市购物小票、家里的说明书全部背在身上**才能结账，那你每次出门都会累得精疲力竭（消耗海量的输入 Token，额度瞬间被吃光）。

## 2. 为什么传统的 AI 很容易变成“Token 吞噬兽”？

传统的 AI 编程助手在面对复杂的开发任务（比如我们刚刚完成的“修复数据库 P0 崩溃”和“重构 H5 自定义底栏图标”）时，通常会犯以下几个“昂贵的错误”：

1. **“整本书背在身上”**：为了改 5 行代码，它会把几百行甚至上千行的整个 Java 文件全量读取一遍，改完后再全量重写一遍。
2. **“疯狂碎碎念”**：在本地编译或者把包上传到远程服务器部署时，黑框框（控制台）里会产生几千行的构建日志。传统 AI 会把这些冗长的日志**逐行读进脑子里**，甚至实时打印在聊天窗口里，这会瞬间吃掉几万个 Token！
3. **“滚雪球式的记忆”**：随着我们聊得越来越深，历史对话像滚雪球一样越来越大，每次你发一个简单的“继续”，AI 都要强行复习一遍之前几万字的历史，导致能耗指数级上升。

## 3. “小步”背后的 Agent 是如何施展“省钱魔法”的？

为了保护您的 Token 额度，我们在 Antigravity（无摩擦自主智能体）中构筑了三层极其硬核的**“省钱魔法阵”**：

### 🔮 魔法一：影子观察者（Shadow Observer —— 精确看，不乱翻）
当您发来一个报错时，我们不会盲目去读取整个项目目录。
* **精准定位**：我们使用超高能效的“强力雷达”（Ripgrep）在 0.1 秒内直接抓取到出错代码所在的具体文件和行号。
* **局部截断阅读**：如果这个文件有 1000 行，我们只使用高精度截断镜，**只看出错行附近的 30 行上下文**。
* **精准做手术**：修改代码时，我们绝对不全量重写文件，而是用一种叫 `replace_file_content` 的“微创手术刀”，**只把修改好的 5 行代码精准替换进去**。这让我们的输入 Token 消耗降低了 90% 以上！

### 🔮 魔法二：后台静默分身（默默干活，不发噪音）
在本次任务中，我们执行了两次重度运维操作：一次是 37 个 Java 模块的全局编译，另一次是将 120MB+ 的后端包和 H5 前端包一键热部署并滚动重启 Docker 容器。
* **标准操作下的灾难**：这两次操作在后台产生了超过 **2,500 行** 冗长枯燥的构建与上传日志。如果全部回吐给 AI，您的 Token 额度会瞬间清零。
* **静默托管**：我们的系统让这些重度日志在操作系统的“后台进程分身”里静默运行，并沉淀在本地的 `.system_generated/tasks/` 文件里。
* **捷报回传**：AI 会在后台安静等待。直到打包上传成功、Docker 滚动重启完毕的瞬间，分身才向主脑回传了一句简短的**“Small Steps 部署完成！”**。**这直接帮您省掉了 95% 以上无意义的传输损耗！**

### 🔮 魔法三：记忆大清扫（Compaction —— 定期整理背包）
当我们的对话历史变得太长、大脑快装不下时，系统会在后台悄悄启动“记忆压缩魔法”。它会把之前复杂的排查过程、长篇累牍的日志**浓缩提炼为一段极简的“高置信度进度纪要”**，然后把旧的垃圾记忆彻底清空。
当您发送“继续”或新请求时，AI 带着最轻量、最干净的记忆重新出发，彻底斩断了“滚雪球”式的额度膨胀。
