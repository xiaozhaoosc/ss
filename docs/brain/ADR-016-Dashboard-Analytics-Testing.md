# ADR-016: 高保真仪表盘报表与自动化测试架构

## 状态
已决策 (Decided)

## 背景
家长端仪表盘作为核心入口，原有设计存在以下痛点：
1. **视觉表现力弱**: 仅有基础文字展示，无法直观反映 AI 资源消耗及孩子行为趋势。
2. **数据死板**: 依赖硬编码的 Mock 数据，缺乏动态感知能力。
3. **回归风险高**: 仪表盘涉及多端数据聚合，每次前端迭代都可能导致报表渲染失败。
4. **图标 404**: 依赖外部 URL (Icons8) 导致在离线或弱网环境下成就墙显示异常。

## 决策
1. **可视化升级**: 
    - 引入 **ECharts** 作为核心引擎。
    - 设计“AI 智能中心”、“潜能雷达”与“行为热力图”三大模块。
    - 核心指标（Token 消耗、额度、负载）实现动态化。
2. **资源本地化**: 
    - 使用 AI 生成高质量成就勋章图标并本地化存储，消除外部依赖。
3. **自动化测试基石**: 
    - 确立 **Playwright** 为 E2E 测试标准。
    - 实现全自动登录、跳过新手引导、ECharts Canvas 渲染验证。
    - 针对开发环境端口冲突（88 vs 9090）建立动态感知机制。

## 后果
- **正面**: 
    - 提升了系统的 Premium 感，增强了家长的信任感。
    - 建立了“Green Build”门禁，前端迭代更安全。
    - 仪表盘响应速度与离线鲁棒性显著提升。
- **负面**: 
    - 增加了前端打包体积（ECharts 依赖）。
    - 测试脚本维护成本增加，需定期同步 UI 变更。
