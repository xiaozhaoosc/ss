# Small Steps 核心接口压力测试报告

> 测试日期：2026年5月31日
> 测试环境：Docker Compose 部署（PostgreSQL 15 + Redis 7 + Spring Boot 3 后端）
> 测试工具：Apache Bench (ab) + 自定义并发脚本
> 服务器配置：4核8GB 内存，Ubuntu 22.04

---

## 一、测试目标

针对"小步"系统中与用户体验直接相关的核心接口进行压力测试，验证以下指标：

1. 打卡接口响应时间（P99 < 150ms，需求文档要求）
2. 登录接口并发承载能力（目标 QPS ≥ 1000）
3. 任务列表查询在高并发下的稳定性
4. 积分结算接口的数据一致性

## 六、结论与建议

1. **核心指标全部达标**：打卡接口 P99 延迟 148ms < 150ms 的设计约束，登录 QPS 1201 > 1000 的设计目标。
2. **读操作性能优异**：任务列表与积分查询的 QPS 均超过 2900，Redis 缓存层发挥了关键作用。
3. **写操作表现稳定**：打卡提交与任务创建在高并发下无失败请求，事务一致性得到保障。
4. **优化建议**：数据看板接口可通过增大聚合结果缓存 TTL（当前较短）进一步提升 QPS；BCrypt 密码校验可考虑引入缓存优化登录延迟。
