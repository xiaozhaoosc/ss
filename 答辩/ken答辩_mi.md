## 二、选题背景与意义（1分钟）

### 2.1 研究背景
ADHD（注意缺陷多动障碍）是学龄期儿童最常见的神经发育障碍之一，全球发病率约5%-7%。核心表现为注意力维持困难、活动过度和行为冲动。

### 2.2 现有方案的不足
- **药物治疗**：需长期服药，存在食欲减退、失眠、影响发育等副作用
- **线下行为干预**：需要专业心理医生指导，家长难以长期坚持，成本高
- **现有App**：多为通用效率工具，认知负担重，缺乏针对ADHD儿童的专门设计

### 2.3 研究目标
设计一套"物理伴侣+游戏化激励"的辅助系统，通过数字化手段实施辅助干预，实现：
- 认知减负：降低儿童使用时的认知负荷
- 亲子协同：构建家长-儿童双端协作闭环
- 动态激励：通过AI生成个性化鼓励与建议

## 三、系统设计与架构（1分30秒）

### 3.1 系统架构
采用前后端分离的三层架构：

```
┌─────────────────────────────────────────────┐
│  移动端 (UniApp X + Vue 3)                   │
│  • 儿童端：游戏化激励、沉浸式体验            │
│  • 家长端：数据看板、任务配置                 │
├─────────────────────────────────────────────┤
│  管理后台 (Vue 3 + TypeScript + Element Plus) │
│  • 任务模板管理、用户管理、数据统计          │
├─────────────────────────────────────────────┤
│  后端API (Spring Boot 3 + MyBatis-Plus)      │
│  • Sa-Token统一鉴权、PostgreSQL + Redis      │
└─────────────────────────────────────────────┘
```

### 3.2 核心业务流程
1. **家长创建任务** → 系统自动指派给儿童
2. **儿童执行任务** → 专注模式计时 → 提交完成
3. **家长审核点亮星星** → 触发积分奖励
4. **AI分析行为数据** → 生成个性化寄语与建议

### 3.3 用户角色与权限
系统采用Sa-Token实现三角色权限隔离：
- **管理员**：系统配置、用户管理、数据统计
- **家长**：任务创建、奖励配置、数据查看
- **儿童**：任务执行、专注打卡、积分兑换

## 四、技术实现与亮点（1分30秒）

### 4.1 技术选型

| 层级 | 技术栈 | 选型理由 |
|------|--------|----------|
| 后端框架 | Spring Boot 3.5.9 + Java 21 | 成熟稳定，生态丰富 |
| ORM | MyBatis-Plus 3.5.14 | 简化CRUD，支持复杂查询 |
| 权限管理 | Sa-Token 1.44.0 | 轻量级，API简洁，支持多账号体系 |
| 数据库 | PostgreSQL + Redis | PostgreSQL支持JSONB，Redis缓存热点数据 |
| 移动端 | UniApp X + Vue 3 + Pinia | 一套代码多端运行，状态管理高效 |
| 管理后台 | Vue 3 + TypeScript + Element Plus | 类型安全，组件丰富 |

### 4.2 核心技术亮点

#### （1）双模式动态切换
利用Pinia状态管理实现家长/儿童模式无缝切换，底部TabBar、配色方案、字体大小等根据角色动态调整。

#### （2）专注模式防误触设计
```javascript
// 拦截物理返回键，防止ADHD儿童误触退出
onBackPress((options) => {
    if (isFocusing.value) {
        uni.showModal({ title: '确认放弃?', content: '现在退出专注将失去当前奖励碎片' });
        return true; // 拦截返回操作
    }
});
```

#### （3）AI智能反馈闭环
- 每日定时任务聚合儿童行为数据（完成率、专注时长、情绪状态）
- 异步调用大模型生成个性化鼓励话术
- 熔断降级机制：连续3次调用失败自动切换为预设话术库

#### （4）Redis缓存优化
- Sa-Token会话缓存：`satoken:login:session:{userId}`
- 任务防重复提交：利用SETNX分布式锁防止快速双击导致重复结算

#### （5）游戏化激励体系
- 代币系统：任务完成 → 星星奖励 → 进度池可视化
- 勋章成就：自动检查并解锁成就徽章
- 奖励兑换：积分兑换家长预设的心愿礼物

### 4.3 数据库设计
采用"关系型数据库+缓存层"双层架构，核心表包括：
- `ss_parent_task`：任务定义表
- `ss_task_log`：任务执行记录表
- `ss_child`：儿童档案表
- `ss_child_score`：积分账户表
- `ss_score_history`：积分流水表
- `ss_parent_reward`：奖励配置表
- `ss_parent_reward_redemption`：兑换记录表

### 7.1 系统特点

## 八、常见问题准备

### Q1：系统用户分类及功能权限？
**A**：系统有三种角色：
- **管理员**：系统配置、用户管理、任务模板维护、数据统计
- **家长**：创建任务、配置奖励、查看数据看板、审核兑换申请
- **儿童**：执行任务、专注打卡、查看积分、兑换奖励

权限隔离通过Sa-Token实现，接口级注解控制（@SaCheckRole、@SaCheckPermission），数据级通过家庭ID（dept_id）隔离。

### Q2：系统所用技术及其特点？
**A**：
- **Spring Boot 3**：自动配置、内嵌服务器、生态丰富
- **MyBatis-Plus**：简化CRUD、条件构造器、代码生成器
- **Sa-Token**：轻量级权限框架，API简洁，支持多账号体系
- **PostgreSQL**：支持JSONB类型，适合存储非结构化数据
- **Redis**：高速缓存，支持分布式锁，用于会话管理和防重复提交
- **UniApp**：一套代码多端运行（H5、小程序、App）
- **Vue 3 Composition API**：逻辑聚合，代码更清晰

### Q3：系统功能设计或技术点方面的优点？
**A**：
1. **双模式设计**：家长端和儿童端使用不同UI风格，降低儿童认知负荷
2. **专注模式防误触**：拦截物理返回键，防止误操作
3. **AI智能反馈**：异步生成个性化鼓励，熔断降级保证可用性
4. **游戏化激励**：代币+勋章+奖励兑换，提升儿童参与度
5. **Redis缓存优化**：会话缓存+防重复提交，提升系统性能

### Q4：测试方法？
**A**：
- **功能测试**：多角色权限测试、任务生命周期测试
- **兼容性测试**：多款安卓真机测试（华为P40 Pro、Mate 30 Pro）
- **安全测试**：横向越权、纵向越权测试
- **性能测试**：核心接口响应时间控制在150ms以内

### Q5：系统有哪些不足及如何改进？
**A**：
1. **数据维度单一**：仅依赖主动打卡，未来可接入智能手表等IoT设备获取心率、血氧等客观数据
2. **AI依赖云端**：调用大模型API存在延迟和隐私风险，未来可探索边缘计算，本地部署轻量化LLM（如Qwen-1.5B）
3. **离线能力有限**：目前弱网环境下功能受限，未来可加强离线缓存和同步机制
4. **硬件集成待完善**：ESP32硬件终端仅完成原型，未来可实现语音唤醒和情感化交互
