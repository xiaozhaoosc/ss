## 二、5分钟自述稿（逐字稿·背诵版）

### 【开场】(~20秒)

各位评委老师好，我是计算机科学与技术专业的赵轩，我的论文题目是《ADHD中小学生行为习惯辅助系统设计与实现》，指导老师是薛庆水老师。接下来我从研究背景、系统设计、核心实现和测试验证几个方面来介绍。

### 【背景与创新点】(~90秒)

先看研究背景。ADHD在学龄儿童中发病率约5%到7%，大约每20个孩子里就有1个。当前困境：药物有副作用，线下行为矫正又贵又费家长时间，市面上现有效率类App对ADHD孩子适配性很差——界面复杂，功能太多。
所以我做的这个项目的目标是：构建一套面向ADHD中小学生的三端协同行为习惯辅助系统，通过数字化手段降低认知负担，缓解亲子冲突。
两个核心创新点。第一，三端协同干预模式——儿童端、家长端和管理后台串联，形成"任务拆解—专注执行—激励反馈—数据优化"的完整闭环。第二，LLM驱动的个性化激励——集成大语言模型，根据孩子行为数据动态生成鼓励话术，引导家长从"监督者"变成"陪伴者"，降低家长的干预负担。

### 【需求与选型】(~50秒)

需求上，三端各有侧重。儿童端极简设计，只有任务展示、专注计时和代币激励三个核心功能，适配ADHD孩子注意力特点。家长端做任务创建、数据看板和AI指导推送。管理后台做用户管理和大模型监控。非功能性需求方面，核心接口响应小于150毫秒，敏感数据加密存储，还支持离线计时。
技术选型上，后端用Spring Boot 3加MyBatis-Plus，权限用Sa-Token，生态成熟，多角色隔离配置灵活。移动端用UniApp加Vue3和Pinia做双模式动态切换，样式用TailwindCSS。数据库选PostgreSQL，因为它支持JSONB灵活存储非结构化行为数据，搭配Redis做缓存。整个选型都考虑了项目实际需求，没有盲目追新技术。

### 【架构与核心实现】(~80秒)

架构上采用经典四层分层：表现层、业务逻辑层、数据访问层和基础层，前后端分离，RESTful API通信。业务上划分了四大核心模块：
第一是认证鉴权——基于Sa-Token全局拦截器，三角色权限严格互斥，支持双域会话隔离。
第二是任务管理——支持大任务拆解成微步骤，比如"刷牙"可以拆成"拿牙刷→挤牙膏→刷左边→刷右边→漱口"五步，用状态机管理任务全生命周期。
第三是专注模式——全屏沉浸计时加防误触，孩子按返回键不会退出，屏幕保持常亮，中断时长自动归档。
第四是LLM智能辅助——定时任务异步聚合行为数据调用大模型，配置了熔断降级，就算大模型接口出问题也有一套预设的兜底话术。
移动端还做了三个亮点设计：双模式动态切换——用Pinia全局状态管理，登录后自动识别角色切换对应UI；专注模式的防误触——拦截返回操作+屏幕常亮；响应式低认知负担UI——用TailwindCSS原子类适配不同尺寸设备，界面简约没有多余元素。

### 【测试与总结】(~60秒)

测试方面，用Docker容器化部署预发布环境覆盖安卓和Web两端。测试维度包括多角色权限隔离和任务全生命周期流转，采用黑盒功能测试与白盒代码审查结合，核心接口做了自动化测试。结果：越权请求全部被拦截返回403，任务流转全链路数据一致性100%，性能响应时间小于200毫秒。结论是核心业务流程稳定，达到上线要求。
总结三点：第一，完成了三端协同的ADHD行为辅助系统全链路开发，所有核心功能落地；第二，验证了LLM在儿童行为干预场景的落地价值，能有效降低家长负担；第三，系统通过了完整测试，核心流程稳定。
未来方向：接入IoT可穿戴设备获取心率、血氧等多模态数据，更精准判断孩子状态；探索边缘大模型本地化部署，保障数据隐私、降低API调用成本。

## 四、常见答辩问题准备（Q&A）

### Q1：系统有哪些用户角色？各有什么权限？
三种角色，权限严格隔离。儿童端只能看自己的任务、执行任务、专注计时、获取积分和兑换奖励。家长端可创建任务、查看数据看板、发放奖励、接收AI建议，但只能管理自己绑定的孩子。管理员有全局权限做用户管理和系统配置。通过Sa-Token加接口级注解实现，管理员和家长还是分开的双域会话。

### Q2：后端用了什么框架？有什么特点？
后端用的是Spring Boot 3.5.9 + Java 21，基于RuoYi-Vue-Plus框架搭建。特点主要有：生态成熟、社区活跃；Sa-Token支持JWT模式和注解鉴权，多角色配置灵活；PostgreSQL的JSONB类型可以灵活存储非结构化数据；Redis做缓存应对高并发；定时任务异步调用LLM，配置熔断降级，不影响核心业务。

### Q3：数据库为什么选PostgreSQL而不是MySQL？
主要两点考虑。第一是JSONB原生支持索引且查询效率高，适合存储本系统的非结构化行为数据和AI生成内容。第二是PostgreSQL在复杂事务处理上更有优势，积分结算和任务流转对数据一致性要求很高。另外用MyBatis-Plus的话，后续即使迁移到MySQL改动量也不大。

### Q4：系统有哪些优点/创新？
主要有四个突出特点。一是三端协同闭环，市面上同类产品很少做完整的。二是LLM个性化激励，基于行为数据动态生成鼓励话术。三是ADHD针对性设计，包括微步骤拆解降低认知负荷、全屏防误触保障专注、极简UI适配注意力特点。四是双模式UI系统，儿童端Nunito圆体加Bouncy动效，家长端系统字体高效专业。

### Q5：系统测试怎么做的？
分三个层面。功能测试方面，黑盒加白盒结合，覆盖了任务创建到积分结算的全链路。权限安全测试方面，测试了横向越权和纵向越权两种场景，全部被拦截返回403。性能测试方面，在Docker预发布环境下压测核心接口，响应时间控制在200毫秒以内。还做了自动化接口测试保证回归效率。

### Q6：系统有什么不足？如何改进？
三点不足。一是缺乏多模态生理数据感知能力，改进方向是接入IoT可穿戴设备如智能手表。二是LLM调用依赖云端，存在隐私和成本问题，改进方向是探索边缘大模型本地化部署。三是数据看板分析维度还不够丰富，后续增加行为趋势图和改善率统计等功能。

### Q7：任务拆解功能的实现逻辑？
通过ss_parent_task表的parentId字段实现。家长创建主任务后可以添加子步骤，子步骤通过parentId关联到主任务。每个子步骤都是一个独立的ChildTask，孩子逐个完成后获取即时反馈。比如刷牙拆成拿牙刷→挤牙膏→刷左边→刷右边→漱口五步，每个小步骤完成后都有反馈，降低孩子的认知负担。

### Q8：LLM在系统中具体怎么应用的？
通过智能辅助生成模块实现。定时任务定时聚合孩子的行为数据，包括最近完成的任务、拖延的任务、情绪变化趋势等，然后异步调用大模型生成个性化的鼓励话术或干预建议。配置了熔断降级策略，LLM接口超时或出错时自动返回预设的兜底话术，不影响用户体验。例如检测到孩子连续三天没完成整理书包，会生成建议告诉家长"小明最近可能感到有些压力，建议今晚睡前用游戏方式一起整理书包"。

### Q9：专注模式防误触怎么实现的？
三个方面。第一是返回操作拦截，专注过程中按返回键会弹出确认对话框，防止误触退出。第二是屏幕保持常亮，不会自动息屏打断专注。第三是中断时长自动归档，即使退出了，已完成的部分也不会白费。

### Q10：Token管理和会话隔离怎么做？
使用Sa-Token的JWT模式。登录成功后服务端生成JWT，通过Authorization头传递。全局拦截器校验Token合法性，再从Token中解析角色和用户ID。接口级权限通过@SaCheckPermission注解控制。家长端和儿童端通过不同的登录入口获取不同域的Token，实现会话隔离。

## 五、答辩记录表 - 第一部分（答辩前写好）

### 1. 选题背景及意义
ADHD全球学龄儿童发病率约5%-7%，我国约有2300万患儿。传统干预方式局限明显：药物有副作用、线下行为矫正门槛高、现有数字化工具对ADHD儿童适配性差。本课题构建三端协同行为习惯辅助系统，以"认知极简+情感温润"为核心理念，通过AI赋能降低家长干预负担，填补面向ADHD群体的数字化行为干预工具缺口。

### 2. 系统总体设计方案
前后端分离分层架构。表现层：UniApp加Vue3移动端和Vue3 Web管理后台。业务逻辑层：Spring Boot 3实现任务流转、积分计算、AI建议生成等核心业务。数据访问层：MyBatis-Plus负责数据库持久化操作。基础层：PostgreSQL数据库加Redis缓存加大模型API代理。前后端通过RESTful API通信，Sa-Token实现多角色鉴权，RSA非对称加密保障数据安全。

### 3. 核心功能模块
认证鉴权模块：三角色权限隔离，Sa-Token加全局拦截器。
任务管理模块：微步骤拆解加状态机全生命周期管理，Transactional事务一致性保障。
专注计时模块：全屏沉浸计时加防误触拦截加屏幕常亮，适配ADHD注意力特点。
积分激励模块：积分发放加奖励兑换加成就勋章，事件驱动架构流水可追溯。
情绪追踪模块：每日情绪记录加趋势分析，PostgreSQL JSONB灵活存储。
LLM智能辅助模块：异步聚合行为数据生成个性化建议，熔断降级加兜底话术。

### 4. 关键技术与创新
关键技术：Spring Boot 3加MyBatis-Plus后端框架、UniApp加Vue3加Pinia跨端移动开发、Sa-Token JWT多角色鉴权、PostgreSQL加Redis混合存储、TailwindCSS原子化样式框架。

创新点：三端协同构建任务拆解到数据优化完整闭环。LLM基于行为数据动态生成鼓励话术，引导家长从监督者转向陪伴者。ADHD针对性设计，微步骤降低认知负荷、防误触保障专注、双模式UI。

### 5. 测试与结论
覆盖权限隔离和任务流转两大核心维度，黑盒加白盒加自动化。结果：越权100%拦截、数据一致性100%、响应小于200ms。结论：核心流程稳定，达到上线标准。

### 6. 不足与改进
缺乏多模态生理感知。LLM依赖云端。数据看板维度不足。分别对应改进为接入IoT可穿戴设备、边缘大模型本地化、丰富统计分析功能。
