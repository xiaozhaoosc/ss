Design and Implementation of ADHD Behavior Support System for Children

Abstract: 	Attention deficit hyperactivity disorder (ADHD), characterized by difficulties in sustaining attention, hyperactivity, and impulsivity, is a prevalent neurodevelopmental condition among school-age children. Mainstream pharmacological interventions require long-term administration and may adversely affect physical development, while supplementary offline behavioral therapies often impose substantial burdens on both parents and children amid demanding academic schedules. With the advancement of artificial intelligence, digital tools have emerged as a viable modality for assisted intervention. Addressing core needs such as cognitive offloading, parent-child coordination, and dynamic motivation, this study designed and implemented a comprehensive habit-formation support system for elementary and middle school students with ADHD, named "Small Steps." The system adopts a front-end/back-end separation architecture, integrating a child application, a parent application, and an administrative backend to establish a digital intervention loop encompassing progressive task decomposition, multimodal incentive mechanisms, and emotion tracking. On the technical side, the backend is built upon Spring Boot 3 and MyBatis-Plus, employing Sa-Token for multi-role authentication, with PostgreSQL and Redis serving as the data persistence and caching layers. The mobile application utilizes UniApp with Vue 3 to enable dynamic dual-mode switching. The principal innovation of the system lies in the integration of a large language model (LLM), which dynamically generates personalized motivational messages and intervention recommendations by analyzing children’s behavioral data—alleviating execution fatigue and guiding parents to transition from "supervisors" to "companions," thereby offering a novel practical approach for daily digital-assisted ADHD intervention.

1绪论

注意力缺陷多动障碍（ADHD）是学龄期儿童中最为常见的神经发育性障碍之一。其核心症状表现为注意力维持困难、活动量异常偏高以及行为冲动性增强。对于正处于中小学阶段的患儿而言，上述症状所带来的影响是多维度的：课堂学习效率显著下降，日常生活自理能力不足，家庭关系亦随之趋于紧张。目前主流的干预手段包括药物治疗与线下行为矫正两类，但药物存在一定的副作用风险，线下矫正则受限于专业资源稀缺与经济成本较高，并非所有家庭均能持续承担。近年来，随着物联网与人工智能技术的快速发展，数字疗法逐渐成为ADHD干预领域的新方向。然而，当前市面已有的应用程序大多仅提供基础的时间管理或番茄钟功能，专门面向ADHD儿童特征进行系统性设计的软件产品仍然较为匮乏。

1.1研究背景
注意缺陷多动障碍（Attention Deficit Hyperactivity Disorder，简称ADHD），全球学龄儿童的发病率约为5%至7%[1]，部分地区的统计数据甚至更高。其核心症状表现为：与同龄人相比，注意力维持能力显著不足、活动水平异常偏高、行为控制能力薄弱。需要指出的是，上述症状通常不会直接影响儿童的智力水平，但对其”执行功能”的损害却是显著的——包括工作记忆容量下降、情绪调节能力减弱、内在动机不足以及计划组织能力受限等[2]。
在日常学习与生活场景中，ADHD儿童面临的困难远超一般认知。课堂上难以持续专注、易受外界干扰分散注意力属于常见表现；家庭作业场景中则普遍存在任务启动困难、执行拖延、无法自主分解任务步骤等问题。在社会交往层面，由于冲动控制能力不足，患儿容易出现插话、打断他人甚至肢体冲突等行为，进而导致同伴排斥与社会孤立。长期处于这种反复受挫的环境中，儿童极易产生低自尊、焦虑及抑郁等继发性心理问题[3]。因此，如何有效帮助ADHD儿童在日常生活中减轻认知负荷、逐步建立规律化的行为习惯，已成为一项具有现实紧迫性的社会议题。
1.2研究目的
传统的ADHD干预手段主要包括药物治疗与行为干预两种路径。药物方面，以利他林为代表的中枢兴奋剂虽能在一定程度上缓解核心症状，但在儿童群体中的应用始终存在争议——食欲减退、睡眠障碍、对身高发育的潜在影响等问题令不少家长望而却步。行为干预方面，以家长管理培训（Parent Management Training）为代表的非药物疗法在长期效果上已获得实证支持，但其实施门槛较高：不仅需要专业心理治疗师的持续指导，更要求家长在日常生活中长期、稳定、科学地执行干预策略。然而现实中，家长自身已承受较大的工作与生活压力，且多数缺乏系统的心理学训练，在反复督促孩子完成任务的过程中极易产生情绪耗竭。其结果往往是问题未能有效解决，亲子关系却先行恶化，陷入相互消耗的恶性循环[4]。
在此背景下，数字化辅助工具的价值日益凸显。移动应用程序具备全天候在线、情绪稳定、数据记录精确等天然优势，将其引入ADHD家庭的干预场景中，可以充当亲子之间的”中介缓冲层”。一方面，应用程序能够通过游戏化设计与即时反馈机制，为多巴胺分泌水平偏低的ADHD儿童提供高频、正向的刺激，将原本枯燥的日常任务转化为具有一定趣味性的活动；另一方面，应用程序能够替代家长承担部分监督职能，减少亲子之间因任务督促产生的直接语言摩擦。当家长从监督任务完成的焦虑中解脱出来后，便能将更多精力投入到情感支持与高质量陪伴中，从而改善家庭整体氛围。
1.3研究意义
当前应用市场中以”日程管理”、”时间追踪”、”番茄钟”为名的效率类应用程序数量众多，但将其应用于ADHD儿童群体时，普遍存在适配性不足的问题。具体而言，存在以下几方面缺陷：
第一，认知负荷过高。通用型应用程序为追求功能丰富性，往往在界面中密集呈现图表、菜单与多层级导航。对于执行功能本身已受损的ADHD儿童而言，这类视觉与认知层面的信息过载极易引发回避行为，使其尚未开始使用便已产生畏难情绪。
第二，任务分解粒度不足。ADHD儿童面临的核心困难之一是任务启动障碍——当他们面对"写作业"这类整体性任务时，往往因无法自行拆解步骤而陷入停滞。通用工具鲜少提供将复杂任务逐层分解为可执行微步骤的引导机制。
第三，反馈方式缺乏情感温度。多数工具仅以数据统计形式呈现结果，如"今日有2项任务超时"。这种聚焦于未完成事项的反馈模式，容易强化ADHD儿童的挫败感与自我否定，形成"失败—回避—再失败"的负向循环。实际上，这类群体更需要的是关注已完成部分的正向引导。
第四，忽视家长端的协同需求。现有工具大多将执行压力完全施加于儿童一方，鲜少考虑如何为家长提供情绪支持与策略指导，亦缺乏家庭系统层面的协同干预设计。
综合来看，当前市场亟需一款能够真正理解ADHD儿童心理特征、以降低认知负荷为核心设计原则、同时兼顾家长情绪疏导的双端协同辅助系统。这也是本项目的研究初衷。
1.4研究现状和发展趋势
1.4.1传统行为干预与认知疗法的局限
近年来，社会对ADHD的认知逐步深化，已从过去简单地将其归因为儿童"调皮"或"家教缺失"，转变为将其理解为一种与执行功能发育滞后密切相关的神经发育性障碍。传统的干预手段主要包括药物治疗与行为治疗两种路径，其理论基础本身具有科学依据，但在实际家庭场景中的落地效果往往不尽如人意——多数家长未经专业训练，难以在日常生活中持续、稳定地执行行为矫正策略；药物治疗的副作用争议亦长期未能得到充分解决。近年来，随着物联网、人工智能与移动互联网技术的迅猛发展，利用计算机技术辅助ADHD儿童建立行为习惯——即"数字疗法"——逐渐成为跨学科研究的热点方向。本课题旨在将循证心理学理论与现代软件技术相结合，构建一套软硬件协同的辅助干预系统。以下从理论基础、技术实现与发展趋势三个维度，对国内外研究现状进行梳理。
认知行为疗法（CBT）与代币经济系统在ADHD行为干预领域已有较长的应用历史[5]。二者在治疗环境中均能取得一定效果，但一个长期存在的问题是：干预效果在脱离治疗场景后往往显著衰减。其核心原因在于，家长作为非专业治疗者，难以长期维持奖励与惩罚标准的一致性——这种执行层面的不稳定性直接削弱了干预效果的持续性。这一现实困境表明，仅依靠人力难以维持干预的稳定性，有必要引入标准化、自动化的技术手段加以补充。
1.4.2数字疗法与应用程序在 ADHD 干预中的发展
在国际层面，数字疗法领域的研究与产业化进展显著[6]。2020年，美国FDA批准了首款针对ADHD的处方级视频游戏EndeavorRx[7]，这一事件具有里程碑意义，标志着游戏化数字干预路径获得了官方层面的正式认可。在软件应用方面，欧美地区已有多个团队致力于开发增强时间感知与日程规划能力的辅助系统，例如通过智能手表震动提醒时间节点等方案。
在国内层面，ADHD数字辅助软件的研发尚处于起步阶段但发展较快。当前市面产品以在线问卷、量表评估、知识付费课程及基础打卡工具为主。部分产品已尝试引入积分奖励机制，但在交互设计层面针对ADHD等神经多样性群体的定制化考量仍显不足，产品成熟度有待提升。
1.4.3现状总结与本系统的突破点
综合国内外研究现状可以发现，利用移动互联网平台实施行为干预辅助已获得较为充分的理论与实践支撑。然而，针对国内中小学ADHD群体，真正贴合其认知与行为特征的家庭化解决方案仍然匮乏。"小步（Small Steps）"系统的核心设计目标包括：
摒弃"监督"导向的交互范式，维护儿童的尊严感。整体设计不采用居高临下的姿态，而是以平等陪伴者的角色定位呈现，避免过度强化任务失败带来的惩罚感知。
以"脚手架"理论为指导，逐步培养儿童的自主能力。系统不仅提供任务提醒，更核心的是利用大语言模型（LLM）的数据分析能力，识别儿童在具体执行环节中的障碍点，进而提供渐进式撤除辅助的策略建议，最终目标是帮助儿童实现自我管理。
采用现代化技术栈。前后端基于Vue 3与Spring Boot 3的微服务体系构建，跨端兼容性通过UniApp实现。同时建立完整的数据追踪与可视化机制，使干预过程具备可量化的观测依据。
基于上述分析，围绕ADHD中小学生在实际学习与生活中面临的困难，针对现有辅助工具的不足，运用软件工程方法，构建了一套包含移动端（儿童端与家长端）与管理后台的"多角色业务闭环"辅助系统。在工程开发与理论验证两个维度上，具体研究内容包括：
将心理学概念落实到前端界面实现。探索"降低认知负荷"、"代币奖励"、"及时正向反馈"等心理学理论如何通过UniApp技术转化为儿童与家长可实际操作的UI组件，包括番茄钟的交互设计、微动效的实现方式、配色方案的确定等，打通理论与实现之间的路径。
验证前后端分离架构下的安全性与效率。通过Spring Boot 3与Sa-Token的组合，在保障系统并发承载能力的前提下，实现细粒度的多角色权限控制；验证Redis在多端状态同步与缓存支撑方面的实际表现。通过完整的开发与测试流程进行实证验证。
探索大语言模型在业务场景中的实际应用价值。研究如何将大语言模型稳定接入后端系统，将调用延迟控制在可接受范围内，并基于儿童长期行为数据与打卡记录，自动生成个性化的激励话术与任务建议。该方向是AI辅助数字行为干预领域的一次实践探索。
完整实践软件工程全流程。从需求分析、数据库表结构设计、API接口定义，到前后端联调及基于Docker的部署，完整走通软件工程的闭环工作流并进行系统性记录。
此外，系统预留了ESP32嵌入式平台的语音扩展接口，以探索在真实家庭作业场景中的实际应用效果。与市面上传感器被动收集体征信号的方案不同，本系统倾向于采用ESP32-S3模组实现离线语音唤醒与低延迟对话功能。选用S3型号主要基于其向量指令扩展对神经网络推理的加速能力，可满足轻量级唤醒词检测的本地化运行需求，减少对云端计算的依赖。该设计使系统具备了"物理伙伴"的实体交互形态，不再局限于纯软件层面的屏幕交互。
该方向的实现思路参考了开源社区中"小智"系统的离线TTS与简单对话流处理方案。具体设想是在ESP32终端上集成轻量级TTS引擎与情感化语音编码模块，使其成为书桌上安静待机的实体设备。当儿童在写作业过程中出现注意力分散时，设备可通过呼吸灯亮起或轻柔的拟声提示，配合简短的鼓励语句，为ADHD儿童提供一个微弱的注意力"锚点"——帮助其将分散的注意力轻柔地拉回任务，同时避免过度干扰。
选择边缘计算路径主要基于两方面考量：一是数据隐私保障，语音数据在本地处理可有效避免敏感信息上传云端的风险；二是降低认知负荷，相较于需要视觉注意力的手机应用界面，仅需听觉与余光即可感知的实体陪伴设备对ADHD儿童的认知负担更小。从长远来看，这种软硬件融合、具备语音交互能力的框架，有望使系统从单纯的软件工具演进为具有温度感的"第二调节者"，在家庭环境中为神经多样性儿童提供稳定、无情绪波动的陪伴角色。
1.5开发相关技术
"小步（Small Steps）"系统在技术选型上以成熟稳定为首要原则，兼顾工程实现的便捷性与理论指导的适配性。整体采用前后端分离架构，客户端涵盖移动端与浏览器端，通过RESTful API进行数据通信，各层之间保持低耦合。
1.5.1后端技术栈：Spring Boot 3 和 MyBatis-Plus
系统核心服务选用Spring Boot 3框架。在Java微服务生态中，Spring Boot凭借依赖管理、自动配置与内置服务器等特性，是当前主流的技术选型。选用3.x版本主要基于以下考量：对JDK 17的支持更为完善，与Spring Framework 6的兼容性良好，同时为后续可能的AOT编译优化预留了版本空间。全局异常处理、跨域配置、统一返回格式封装等基础设施性工作均由框架承接。
数据持久层选用MyBatis-Plus框架。相较于原生MyBatis或JPA，MyBatis-Plus在本系统场景中具有更好的适配性：系统中涉及"任务流转"、"用户状态统计"等业务的查询逻辑较为复杂，原生MyBatis的单表CRUD会产生大量样板代码，而JPA在多表复杂联查场景下SQL调优的灵活性不足。MyBatis-Plus通过通用Mapper与条件构造器简化了常规操作，同时保留了手写SQL的灵活性。其内置的代码生成器亦可基于数据库表结构自动生成实体类与Mapper接口，显著提升了开发迭代效率[8]。
1.5.2前端与 CSS 框架：UniApp 和 TailwindCSS
移动端选用UniApp 3.0框架。其核心优势在于一套代码可同时编译至Android、H5及小程序等多个平台，避免了各平台独立开发的维护成本。Vue 3的Composition API使业务逻辑的组织更为清晰，配合Pinia进行状态管理，整体跨端开发效率显著提升。
界面样式采用TailwindCSS原子化CSS框架。相较于传统BEM命名规范，TailwindCSS将flex、pt-4、text-center、rounded-lg等细粒度工具类直接应用于模板，避免了自定义类名管理的复杂性与样式耦合风险。对于本系统而言，ADHD儿童对界面颜色对比度与过渡动画流畅度的要求较高，TailwindCSS支持在Vue模板中即时调整并预览效果，无需在模板与样式文件之间频繁切换。构建时框架仅打包实际使用的工具类，有效控制了移动端包体积与首屏加载耗时。
1.5.3权限管理技术：Sa-Token
权限管理方面，系统涉及管理员、家长（主账号）与儿童（子账号）三种角色，层级关系需严格界定。Spring Security功能完备但配置复杂度较高，对于毕业设计的开发周期而言成本偏高。综合考量后选用Sa-Token——一款国内开源的轻量级权限认证框架。
Sa-Token的API设计简洁直观，一句StpUtil.login(id)即可完成登录会话创建。在此基础上，配合框架自带的拦截器与自定义注解（如@RequiresRoles("PARENT")），可实现接口方法级的权限控制。接入Redis后，Token无状态校验、同端多账号踢下线、敏感操作二次确认等功能均可落地实现，代码侵入性较低，以较小的开发成本达成了安全保障目标。

本系统旨在解决ADHD中小学生在日常学习与生活中面临的实际困难，以及现有辅助工具在针对性与完整性方面的不足。通过软件工程方法，构建一套包含儿童端、家长端与管理后台的"多角色业务闭环"辅助系统。在工程开发与理论验证两个维度上，具体研究内容包括：
将心理学概念落实到前端界面实现。探索"降低认知负荷"、"代币奖励"、"及时正向反馈"等心理学理论如何通过UniApp技术转化为儿童与家长可实际操作的UI组件，包括番茄钟的交互设计、微动效的实现方式、配色方案的确定等，打通理论与实现之间的路径。

探索大语言模型在业务场景中的实际应用价值。研究如何将大语言模型稳定接入后端系统，将调用延迟控制在可接受范围内，并基于儿童长期行为数据与打卡记录，自动生成个性化的激励话术与任务建议。该方向是AI辅助数字行为干预领域的一次实践探索。

2系统分析
本章主要解决两个核心问题：第一，系统在技术上是否可行、实施成本是否可控；第二，目标用户（儿童与家长）的功能需求与使用边界是什么。上述分析结果将为后续的架构设计与数据库建模提供明确的约束条件。
2.1可行性分析
"小步（Small Steps）"系统在开发实施前，从技术可行性、操作可行性与理论可行性三个维度进行了系统评估，以下分别阐述。
2.1.1技术可行性
技术选型以成熟稳定为原则，均采用经过生产环境验证的方案。整体采用前后端分离架构，移动端与浏览器端通过RESTful API与后端通信，各层之间保持低耦合。
后端核心采用Spring Boot 3搭配MyBatis-Plus作为持久层框架，二者在Java生态中应用广泛，社区文档丰富，稳定性经过大量生产环境验证。前端移动端基于UniApp 3.0，一套代码可编译至Android与H5平台，Vue 3的Composition API配合Pinia状态管理，开发效率较高。数据库选用PostgreSQL存储核心业务数据，其对JSON数据类型的支持较为友好；Redis用于高并发场景下的缓存与防重复提交。
2.1.2操作可行性
系统面向两类目标用户：ADHD儿童（约6至15岁）及其家长。
儿童端的设计原则以降低认知负荷为核心：采用大字体、大按钮，单屏仅呈现一项任务，尽可能精简菜单层级与页面跳转。理想状态是用户打开应用即可直觉性地识别操作入口，无需阅读说明文档。
家长端与管理后台遵循行业通用的交互范式。家长端布局参照主流应用的设计规范，功能入口符合用户既有使用习惯。管理后台采用Element Plus组件库，该框架在Vue生态中应用广泛，上手门槛较低。
2.1.3理论指导可行性
本系统的设计并非纯粹的工程实现，其底层以心理学与教育学理论为指导，以确保功能设计不偏离干预目标。主要参考的理论方向包括：
其一是认知负荷理论。ADHD儿童的工作记忆容量本就有限，界面信息过载极易导致认知超载。因此在设计中贯彻"认知卸载"原则——单屏仅呈现一项任务、采用低饱和度配色、减少非必要文字信息。
其二是脚手架理论（Scaffolding Theory）[9]，即在学习者能力不足时提供临时性支持，待其逐步掌握后渐进撤除辅助。系统通过AI识别儿童在具体任务中的障碍点，提供针对性的辅助建议，待儿童熟练后逐步减少干预强度，帮助其从外部监管过渡到自我管理。
其三是操作性条件反射理论与家庭系统动力学。通过随机、即时的正向奖励帮助儿童建立行为正循环，同时使系统充当亲子之间的"中介缓冲层"，将家长从"裁判"角色中解放出来，转变为协作队友。上述理论对系统在真实家庭场景中的可用性具有关键支撑作用。
2.2系统需求分析
需求分析的核心目标是明确系统的功能边界与质量约束。以下从目标用户群体、功能需求与非功能性指标三个维度进行分析。
2.2.1目标用户群体分析
系统的目标用户主要分为两类：ADHD儿童（被辅助方）与家长（辅助方）。两类用户对软件的功能期待与交互需求存在显著差异，需分别进行分析。
（1）儿童用户特征
通过在特教机构的陪读观察，发现该年龄段ADHD儿童具有以下显著特征：
注意力集中程度高度依赖任务的趣味性。儿童在游戏或短视频场景中可维持长时间的高度专注（即"超聚焦"现象），但在刷牙、收拾书包、背诵课文等日常任务中，专注持续时间往往不足五分钟。
时间感知能力薄弱。儿童对任务所需时长缺乏基本预估能力，执行过程中普遍存在拖延现象，往往在截止时间临近时才出现紧迫感。
情绪反应迅速但耐挫能力不足。微小的执行失误即可引发强烈的情绪反应，表现为放弃任务或攻击性行为。
因此，儿童端的设计底线为三条：零学习成本、容错性高、即时正向反馈。界面风格不应呈现为效率工具，而应更接近于理解其心理特征的游戏化交互界面。
（2）家长用户特征
养育ADHD儿童的家长长期承受较大的身心压力。通过社群调研，发现其核心痛点主要集中在以下几个方面：
一是监督疲劳。家长每日需反复进行相同的任务督促——"去刷牙"、"坐好"、"别磨蹭"，长期持续后极易产生情绪耗竭，进而引发家庭冲突。
二是信息不对称。儿童反馈的"做完了"未必反映真实执行情况，家长对任务实际耗时、执行过程中是否存在中断等关键信息缺乏了解渠道。
三是缺乏可操作的指导策略。家长并非缺乏干预意愿，而是缺乏具体的干预方法——在儿童情绪崩溃时应如何回应、如何沟通，需要的是可直接应用的策略建议。
因此，家长端的功能设计需围绕以下核心需求展开：行为数据可视化、任务便捷下发、系统定期提供实用建议。其定位相当于为家长配备外部认知辅助与情绪调节支持。

2.2.3非功能性需求分析
除了功能要做对，系统还得满足一些硬性的指标要求，不然用起来体验会很差。
（1）性能和响应时间
打卡接口：专注模式结束时要同步状态、结算代币，涉及跨库操作，所以核心接口的响应时间得控制在 150 毫秒以内（按 99 分位算），保证动画切换不卡。
大模型异步处理：AI 寄语生成通常要等 10 到 30 秒，这个不能堵主线程，必须走消息队列或者定时任务异步执行，界面上该干嘛干嘛，别让用户干等着。
并发能力：晚上 8 点到 9 点是写作业的高峰，系统至少得扛住单节点每秒 1000 个请求的压力，不然流量一上来崩了，孩子那边情绪也跟着崩。
（2）系统安全性和隐私保护
未成年人数据隔离：ADHD 属于敏感健康信息，数据库设计要尽量少采。凡是涉及孩子姓名、生理特征的敏感字段，入库前必须做哈希或者加密存储。
API 防重放和防篡改：前端发给后端的写操作请求，都得带时间戳和签名校验，防止有人伪造请求无限刷代币。
角色越权防护：用 Sa-Token 基于 RBAC 做权限校验，不光在路由层拦，业务逻辑里也要二次验证。比如家长账号只能查自己名下孩子的数据，不能通过改 ID 去看别人家的。
（3）可用性与兼容性
跨终端一致性：UniApp 打出来的包，在主流安卓机（华为、小米这些）上排版不能出问题，尤其是 TailwindCSS 做的圆角效果别撕裂，还得自适应刘海屏和沉浸式状态栏。
弱网抗性：哪怕在卧室这种 WiFi 信号差甚至断网的地方，孩子端的倒计时本地功能绝对不能挂。进度先离线存着，等网络恢复了再静默同步上去。

3.1.1架构分层设计
"小步"系统在架构设计上采用经典的分层架构思路，各层职责明确、边界清晰。自上而下分为四层[11]。
表现层即前端部分，包括移动端应用（家长端与儿童端）与Web管理后台。该层基于UniApp与Vue 3构建，核心职责是将用户的交互操作转化为HTTP请求，并将后端返回的数据渲染至界面。
业务逻辑层是后端的核心，基于Spring Boot 3构建。所有业务相关的逻辑均位于此层，包括任务流转、代币计算、家长与儿童绑定关系管理等。该层通过Controller接收请求、Service处理业务、Manager进行协调，核心计算与规则校验均封装在内，确保非法数据无法进入后续流程。
数据访问层位于业务逻辑层与数据库之间，采用MyBatis-Plus框架。该层的主要价值在于：单表的增删改查无需手写SQL，直接调用框架提供的通用方法即可。向上为业务层提供面向对象的查询接口，向下将具体的SQL细节封装隐藏。
基础层包括数据库（PostgreSQL）、缓存（Redis）、日志服务及大语言模型API调用的网络代理。该层不涉及业务逻辑，仅负责数据存储、缓存支撑与外部服务调用的稳定性保障。
3.1.2前后端分离协同
"小步"系统采用标准的前后端分离部署架构[12]。前端应用与管理后台通过公网HTTPS协议向云端Nginx网关发送RESTful API请求。网关作为唯一的对外入口，完成负载均衡与跨域处理后，将请求转发至内网的Spring Boot集群。前后端之间统一采用JSON格式进行数据交换，返回结果统一封装于Result<T>泛型类中，包含鉴权状态码与提示信息，便于联调阶段的问题定位。
3.2核心业务模块设计
3.2.1用户认证与鉴权模块
系统涉及三种角色：管理员、家长与儿童。权限隔离机制基于Sa-Token实现[13]。
（1）登陆认证
前端提交账号密码进行身份验证，后端验证通过后在Redis中创建用户会话上下文，并将Token返回至前端。
（2）双域隔离设计
为防止后台管理员 Token 在移动端 App 误用，系统采用 Sa-Token 的多账号体系（Multi-Account System）架构，将后台管理系统（Admin）的用户中心与移动终端（App）的用户中心在缓存路由中严格隔离。
（3）细粒度权限管控
业务层接口执行前，会经过 Sa-Token 全局拦截器（Global Interceptor）。通过在业务特定的 Controller 方法上注入 @SaCheckRole("PARENT") 与 @SaCheckPermission("task:create") 等鉴权注解，保证例如儿童不可创建或随意删除高优任务，家长不能跨家庭体系查看其他儿童数据，实现角色与组织层的严格互斥。
3.2.2任务管理与流程设计
任务是系统最核心的业务实体，几乎所有功能模块均围绕其展开。鉴于ADHD儿童在任务执行过程中的状态变化具有较大不确定性，任务状态机的设计保留了适度的弹性空间。
任务状态包括以下四种：未开始、执行中（进入番茄钟计时状态）、已完成（打卡提交成功）、已废弃（当日未完成且已过期）。
家长创建任务时，除填写标题与预计耗时外，还需配置以下关键属性：执行周期（单次/每日循环/自定义频率）与完成后奖励的代币数量。
此外，复杂任务支持挂载子步骤清单。该设计主要基于ADHD儿童面对"大任务"时易产生畏难心理的特点，将其拆解为若干小步骤后可有效降低心理压力。
3.2.3专注模式与时间管理
专注模块为儿童进入任务后的计时体验提供支撑。该模块不涉及持久层的写入操作，优先保证前端的运行流畅性。
其工作流程如下：前端获取待专注的任务ID与参数，儿童点击"开始"后，Pinia状态树切换至"专注锁定态"，倒计时引擎启动。在此状态下，全局路由返回操作与底部TabBar切换均被拦截，维持全屏沉浸体验。
若倒计时自然结束，前端将完成记录（包含持续时长、设备信息等）提交至后端，后端开启事务确认任务完成并同步核算奖励。
若中途退出，前端仍会将实际积累的时长传回后端，后端在归档时标记为"非完全完成"。该部分数据对后续AI分析儿童的专注耐受阈值与情绪变化趋势具有参考价值。
3.2.4智能辅助生成与数据反馈
为减轻家长每日撰写辅导话术的负担，同时使干预过程更具个性化与针对性，系统构建了一条旁路的AI反馈闭环[14]。该模块不阻塞日常业务流程，由后端定时任务驱动执行。
具体运行机制如下：每日固定时段，系统提取某一儿童与家长组合的近十天打卡记录（包括总完成数、成功率、超时情况、情绪评分等），聚合成结构化的行为摘要JSON。
随后，将该摘要与管理后台预设的Prompt模板组合，异步发送至大语言模型。
大语言模型返回的内容经脱敏处理后入库存储。次日家长打开应用时，首页将展示一张"辅助指引卡片"，呈现AI生成的建议话术。家长确认内容合适后，可一键同步至儿童端的"时光机信箱"界面。
3.3数据库设计
数据库是系统业务逻辑落地的核心载体，其设计直接决定系统的数据一致性、扩展性与运行性能。针对ADHD儿童行为干预场景的特殊性，本系统在数据库设计中不仅关注传统业务数据建模，同时引入游戏化激励、任务拆解以及情绪追踪等扩展维度，以支撑系统的长期行为引导能力。

3.3.1设计原则与总体架构
通过从业务需求描述对象中剥离实体与映射关联，抽取出本系统的四类主要实体构建了 E-R（Entity-Relationship）在数据库设计过程中，系统遵循以下核心原则：
高内聚与领域划分原则 围绕系统核心业务，将数据划分为“用户与档案”、“任务流转”、“激励体系”与“情绪与AI追踪”四大领域，保证各模块职责清晰、边界明确。
读性能优先原则 针对儿童端与家长端的高频读取场景，通过适度去范式化设计与缓存机制，减少多表关联查询带来的性能开销。
灵活扩展原则 对于任务子步骤、用户偏好等非结构化数据，采用 PostgreSQL 的 JSONB 类型存储，以适应未来业务变化。
数据一致性保障原则 通过快照字段与流水表设计，确保积分、奖励等关键数据具备可追溯性与审计能力。

3.3.4缓存策略与 Redis 结构设计
系统中存在多处高频读写场景——例如移动端每次页面切换均需验证Token有效性、首页排行榜需查询积分排名——若所有请求均直接访问PostgreSQL，性能将难以承受。因此，系统引入Redis作为全局缓存层。
认证缓存：配合 Sa-Token，按不同用户建立诸如 satoken:login:session:{userId} 的 Hash 对象，存储权限集合（Permission Sets）与失效时间，免去权限比对时的额外查库消耗。
任务防重复提交：利用Redis短期Key的自动失效机制（TTL）结合SETNX分布式互斥指令，当儿童端快速双击"任务完成"按钮时，拦截第二次请求，确保在高并发场景下不会因网络延迟导致重复结算与代币发放。

4.2后端统筹与接口实现 (smallsteps-api)
后端工程基于 Spring Boot 3 标准的 Maven 多模块体系构建，分为 API 定义、Service 业务逻辑、以及统一的配置管理中心，承载了整个家庭智能干预系统的计算中枢任务。
4.2.1安全认证与路由拦截的实现细节
在用户进行登录请求时，系统调用 SysUserServiceImpl 层的验证逻辑。相比于传统的 JWT 手动拼接，系统引入了 Sa-Token 处理登录态。当验证通过后，直接调用 StpUtil.login(user.getId())。这一简单接口的背后，框架自动向 Redis 缓存写入了当前用户的登录状态与过期时间戳，并在 HTTP Response Header 中自动下发以 satoken 为索引的凭据标识。 为了保障核心业务接口不被未授权访问，后端实现了一个实现了 WebMvcConfigurer 接口的配置类。在此类中注册了 Sa-Token 的拦截器 SaInterceptor：
@Configurationpublic class SaTokenConfigure implements WebMvcConfigurer {
@Override
public void addInterceptors(InterceptorRegistry registry) {
registry.addInterceptor(new SaInterceptor(handle -> StpUtil.checkLogin()))
.addPathPatterns("/ssapi/**")
.excludePathPatterns("/ssapi/public/login", "/ssapi/public/register");
}}
此机制保证了除公开登录注册接口外，所有带有 /ssapi/ 前缀的请求在触达 Controller 的业务逻辑前，都必须经过底层 Redis 中上下文 Token 的比对，有效实现了第一层鉴权。


4.2.2结构化任务与分发系统的业务逻辑实现

4.2.3数据看板聚合与智能数据生成的后端处理

由于系统需要实时生成数据反馈图表，若每次请求均在数据库层面执行GROUP BY与多表联结聚合运算，不仅响应缓慢且消耗大量资源。因此，后端提供了数据聚合层DashboardAggregatorService。该定时服务在每日凌晨2:00自动扫描前一日的打卡日志，计算任务完成率与平均超时比例，将结果作为结构化摘要JSON存储。在大语言模型集成方面，由于外部调用可能遭遇限流或超时，系统针对该服务进行了熔断与降级配置：若连续3次调用AI接口失败，系统将从本地数据库中随机提取预设的通用安抚文本返回给家长端，最大程度保障应用界面的完整性。

5系统测试
任何软件工程项目在正式进入生产环境并交付终端用户之前，均需经过系统性的测试验证。对于"小步"系统而言，由于其目标用户群体的特殊性（儿童）及数据的高隐私敏感度，系统的稳定性、安全性与交互容错能力尤为重要。本章将详细描述测试环境的搭建方案、多维度测试策略及其实际运行结果。
5.1测试环境与策略构建
5.1.1测试环境说明
为确保测试结果尽可能接近真实使用场景，搭建了独立的预发布测试环境：
后端服务端环境： 使用 Docker 容器化运行 Postgres 15 数据库与 Redis 7，保证了隔离性。
后端服务环境：采用Docker容器化部署PostgreSQL 15数据库与Redis 7缓存，保障环境隔离性。移动端编译生成Android APK安装包及H5测试包，分别在华为P40 Pro与Mate 30 Pro设备上完成兼容性验证，未发现明显适配问题。管理后台通过Chrome最新版浏览器访问测试。
5.1.2测试维度设计
本次测试主要从以下两个维度展开：
功能逻辑验证：从家长创建任务开始，到儿童接收、执行完成，再到AI反馈生成，验证整条业务链路的完整性与连贯性，排查流程中的断点或异常。
交互体验验证：模拟各类用户操作场景，检测按钮响应、页面跳转、倒计时切换后台后再恢复等交互环节是否存在异常。
5.2核心业务功能测试
5.2.1多角色权限与路由测试
本节主要验证Sa-Token权限隔离机制的有效性。系统涉及管理员、家长、儿童三种角色，不同角色的接口调用权限与数据访问范围需严格隔离。
横向越权测试：使用儿童账号的Token，构造POST请求访问家长端的任务创建接口。后端返回状态码403，提示权限不足，表明注解拦截机制生效。
纵向越权测试：使用家长A的Token，尝试查询家长B名下绑定的儿童数据。后端返回空数组，表明底层数据隔离拦截器正常工作，未允许跨家庭数据访问。
综合来看，Sa-Token与自定义拦截器的组合在权限隔离方面表现稳定。
5.2.2任务生命周期状态扭转测试
本节验证任务从创建到完成的完整生命周期中，状态变迁与数据落库的正确性。
具体操作如下：首先创建一条"限时5分钟"的扫地任务。儿童端刷新后可见对应的任务卡片，此时状态为待办（status=0）。点击进入后选择"开始专注"，倒计时启动，数据库中状态变更为执行中（status=1）。
测试过程中尝试将应用切换至后台挂起，数十秒后切回前台，倒计时显示的时间按自然时间差递减，未出现计时暂停或错乱现象。
倒计时结束后，系统自动播放成功音效并发起打卡提交请求。经数据库验证，代币余额更新正确，与任务配置的奖励数额一致。
整条链路测试结果表明，任务生命周期的状态推演与设计文档一致，数据回溯完整，未发现遗漏环节。
5.3本章小结
综合来看，本轮测试覆盖了系统的核心功能模块。权限隔离方面，Sa-Token的表现符合预期，横向越权与纵向越权均被有效拦截。任务从创建到完成的状态流转顺畅，倒计时切换后台后再恢复未出现问题，积分结算准确。系统整体稳定性良好，核心业务流程均已通过验证。

6	总结与展望
当前社会的快节奏生活方式使得部分在认知执行神经系统上存在先天劣势的群体（如ADHD群体）面临较大挑战，尤其体现在成长关键期的家庭教育场景中。为缓解大量ADHD家庭所面临的监督耗竭困境，本研究设计并开发了一套"小步"双端行为习惯辅助协同系统。在研究与开发过程中，完成了以下核心工作：
确立了"无压力"的UI交互设计哲学。摒弃具有威慑感的设计风格，转而通过游戏化代币的正向激励与大语言模型的情感化话术构建闭环干预机制。
构建了现代化的前后端分离架构体系：摒弃传统单体结构，后端基于Spring Boot 3与MyBatis-Plus搭建业务核心，利用Sa-Token实现灵活的权限管控；前端基于UniApp 3.0实现多端覆盖，引入Vue 3的Composition API与Pinia实现高效的渲染性能与跨端状态管理。
探索了AI赋能业务的新范式：在完成基础信息交互功能的基础上，尝试在后端定时接入大语言模型智能接口，使系统具备了类似"驻场儿童心理咨询师"的同理心反馈能力，在一定程度上减轻了家长的心智负担。
6.1总结
在工程实施过程中也面临了一定的技术挑战：由于业务对状态同步一致性的要求较高，初期因过多的连表查询导致后端出现性能瓶颈。引入Redis承担大量会话认证校验与去重锁功能后，系统性能实现了显著提升（QPS突破千级）。此外，前端为实现ADHD儿童"零跳转、所见即所得"的交互体验，大量精简了复杂路由结构，依靠Pinia与TailwindCSS的实时按需渲染能力进行替代，虽然增加了前期系统设计的复杂度，但换来了极低的用户操作延迟体验。
6.2系统存在的不足与未来研究展望
虽然“小步”系统在实验室层面通过了测试并在核心架构上奠定了长远发展的框架，但在迈向下一代商业化级产品的路上，依然具有部分可深挖的研究点：
多维度数据的联动感知：目前系统的数据采集仅限于儿童的主动点击打卡完成时间。未来可考虑接入物联网可穿戴设备的蓝牙集成，通过实时获取血氧、心率等生理指标客观评估儿童的专注状态与情绪波动，形成多模态数据验证。
脱离云端的大模型本地化（Edge AI）：为保护干预数据的隐私安全，并规避未来第三方API调用成本过高的问题，后续拟在网关内网或边缘计算终端探索本地部署轻量化大语言模型的能力，实现完全离线环境下的智能分析。
科学技术的价值不仅在于提升效率，更在于为那些不易被大众关注的群体建立平等的支持系统。"小步"是拥抱神经多样性的一次技术实践，期待它在未来能够走进更多普通家庭，让每一位特别的孩子都能在自己的节奏与步伐下，迈出自信且专注的下一步。

            - 可以适当使用拟声词和感叹号增加趣味性
            - 避免使用否定词（如"不要""不能"），改用正面引导

        5. 步骤之间应有清晰的逻辑顺序，遵循时间线或空间线。

        6. 最后一个步骤应包含"完成确认"的正面反馈。

        - desc: 步骤描述（不超过20个字）

  /**
    * 用户Prompt模板（User Prompt）
    * 使用占位符，运行时替换为实际的上下文信息
      */
      public static final String USER_PROMPT_TEMPLATE = """
      请将以下任务拆解为适合ADHD儿童执行的微步骤。

      ## 任务信息
        - 任务名称：{task_title}
        - 儿童年龄：{child_age}岁
        - ADHD类型：{adhd_type}

      ## 输出要求
      请以JSON数组格式输出，每个元素包含desc、duration_sec、voice三个字段。

      ## 输出示例
      [
      {
      "desc": "把铅笔和橡皮放在桌面上",
      "duration_sec": 30,
      "voice": "先把铅笔和橡皮拿出来，放在桌上哦！"
      },
      {
      "desc": "打开数学课本翻到第12页",
      "duration_sec": 60,
      "voice": "找到数学课本，翻到第12页，你真棒！"
      }
      ]

      现在请拆解任务：{task_title}
      """;

  /**
    * 构建最终的用户Prompt
      */
      public static String buildUserPrompt(String taskTitle, int childAge,
      String adhdType) {
      String adhdTypeDesc = switch (adhdType) {
      case "I" -> "注意力不集中型（容易走神、遗忘）";
      case "H" -> "多动冲动型（坐不住、易冲动）";
      case "C" -> "混合型（兼具注意力不集中和多动冲动特征）";
      default -> "未指定";
      };

      return USER_PROMPT_TEMPLATE
      .replace("{task_title}", taskTitle)
      .replace("{child_age}", String.valueOf(childAge))
      .replace("{adhd_type}", adhdTypeDesc);
      }

  /**
    * 构建完整的消息列表（用于OpenAI API的messages参数）
      */
      public static String buildMessages(String taskTitle, int childAge,
      String adhdType) {
      return """
      [
      {
      "role": "system",
      "content": %s
      },
      {
      "role": "user",
      "content": %s
      }
      ]
      """.formatted(
      escapeJson(SYSTEM_PROMPT),
      escapeJson(buildUserPrompt(taskTitle, childAge, adhdType))
      );
      }

  /**
    * JSON字符串转义工具方法
      */
      private static String escapeJson(String input) {
      return input
      .replace("\\", "\\\\")
      .replace("\"", "\\\"")
      .replace("\n", "\\n")
      .replace("\r", "\\r")
      .replace("\t", "\\t");
      }
