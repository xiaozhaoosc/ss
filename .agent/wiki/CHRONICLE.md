# Small Steps 项目编年史 (CHRONICLE)

## [2026-05-29] 帮助与反馈全栈闭环全链路落地
- **事件**: 成功将帮助与反馈功能打通，从移动端 APP 多图真实上传、防越权入库、到后台看板表格审批查看。
- **决策**:
  1. **防御性防越权架构**: 在控制器端利用 `LoginHelper.getUserId()` 强制覆盖前端参数，全面隔绝横向越权数据提交。
  2. **物理联表性能分页**: MyBatis 手写 XML 语句通过 `LEFT JOIN sys_user` 联表同时获取反馈记录与反馈提交人的头像及昵称信息，确保后台看板极佳的视觉表现与极轻量负载。
  3. **ADHD 关怀交互**: 重新规划反馈界面。图片右上角采用轻弹簧微交互角标；内容为空时提交按钮自动显示 HSL 柔和禁用色并禁止点击以安抚情绪，防止高频躁狂误触。
  4. **大图灯箱无感加载**: Web 管理端表格内置 Element Plus 的高级灯箱功能，缩略图直观预览、点击直达交互，提升运营人员的工作效率。
- **影响**: 标志着 Small Steps 的用户意见反馈体系正式具备生产交付实力，提供了完美的闭环系统。

## [2026-05-03] 全栈 CI/CD 交付体系与测试稳定性基座确立
- **事件**: 建立了基于 GitHub Actions 的全自动回归流水线，并解决了长期干扰 E2E 测试的“引导弹窗”随机性问题。
- **决策**: 
  1. **无感测试模式 (Headless Optimized Mode)**: 通过在应用核心组件（`OnboardingOverlay.vue`）中植入 `VITE_SKIP_TOUR` 开关，实现了测试环境对用户引导层的全局、彻底屏蔽，避免了 brittle selectors（脆弱的选择器）。
  2. **会话持久化 (Session Persistence)**: 统一采用 Playwright 的 `storageState` 机制进行全局登录态注入，将单次全量测试时间缩短了 30%，并消除了重复登录产生的 Flakiness。
  3. **基础设施代码化 (Infra-as-Code)**: 编写了包含 PostgreSQL/Redis/Wait-on 逻辑的 `.github/workflows/e2e-tests.yml`，标志着项目正式具备了生产级的质量门禁。
- **影响**: 将开发者的关注点从“修复测试脚本”转移到“编写业务逻辑”，极大地提升了研发交付的信心。

## [2026-04-28] 影子观察者 (Shadow Observer) V1 核心架构确立

  3. **数据驱动的 Scaffolding**: 建立 `ss_task_template` 标准库，通过“一键导入”降低家长的操作负荷，同时为孩子提供结构化的物理引导。

## [2026-04-28] 家长洞察模块稳定性专项加固 (Parent Insight Stabilization)
- **事件**: 解决了困扰多日的后端权限拦截与数据库认证失败问题，实现了 H5 端交互的全面通畅。
- **决策**: 
  1. **超级管理员特权 (Superadmin Bypass)**: 在 `ChildAIController` 等核心控制器中增加了 `LoginHelper.isSuperAdmin()` 判定，允许 `admin` 账号直接查看儿童数据，解决了“无权访问”的业务阻塞。
  2. **基础设施加固**: 同步了本地开发环境与生产环境的 PostgreSQL 认证信息，消除了登录阶段的 500 报错。
  3. **防御性 CSS 架构**: 引入了基于 `pointer-events` 的全局遮罩层治理方案，彻底解决了 `uni-mask` 拦截点击的交互 Bug。
- **影响**: 标志着家长洞察模块从“开发中”正式转入“稳定可用”状态，实现了数据流与交互流的完美闭环。

## [2026-04-28] UniApp H5 交互兼容性专项治理
- **事件**: 彻底解决了长期困扰 H5 环境的 `uni-mask` 点击拦截 P0 级问题，并优化了多端导航栏冲突。
- **决策**: 
  1. **防御性 CSS 架构**: 引入了基于 `pointer-events` 的全局遮罩层治理方案，将原本“一刀切”的阻断式交互改为“按需阻断”，极大提升了系统的容错能力。
  2. **端侧隔离优化**: 在 `App.vue` 生命周期中增加了 H5 特有的 `uni.hideTabBar()` 强制执行逻辑，消除了原生组件对自定义 UI 的底层干扰。
- **影响**: 解决了多份 Bug 报告中提到的“页面卡死”假象，显著降低了用户的心理压力，符合“Cognitive Ease”的核心设计准则。
