# Workflow: /autoTests

## 0. 目标
自动化执行 Playwright 测试，捕获核心路径截图，并利用 LLM 将技术报告转化为用户友好的《操作手册》。
同时保留 Agent 浏览器控制能力作为复杂场景的辅助调试手段。

## 1. 步骤 (Progress)
// turbo-all

// turbo: true
- [ ] **初始化环境检查**: 确保 `node_modules` 存在且 Playwright 已安装。
- [ ] **(Optional) 检查服务**: 确认 Web 服务 (localhost) 是否存活。

// turbo: true
- [ ] **执行测试 (Headless Script)**: 运行 `npx playwright test --reporter=list`。此步骤将生成原始 MD 报告和截图。

- [ ] **[可选] 辅助调试 (Hybrid Mode)**: 
    > 若脚本覆盖不全或需探索新页面，请指示 Agent: "**启动浏览器控制模式**"。
    > Agent 将使用 `puppeteer`/`browser_subagent` 工具手动介入，实时验证复杂的 UI 交互或探索未知路径。

// turbo: true
- [ ] **定位产物**: 查找 `tests/` 目录下最新的 `.md` 报告文件 (按时间戳排序)。

- [ ] **分析并生成**: 读取报告内容，提取步骤与截图，编写《操作手册》。(此步骤需 LLM 深度思考，不可 Turbo)

- [ ] **归档产物**: 保存为 `操作手册_YYYYMMDD.md` 并通知用户。

## 2. 转换指令 (Prompt)
在执行“分析并生成”步骤时，请严格扮演 **技术文档专家**：

> **输入**: 原始测试报告 (包含 `步骤:...(成功)`, `APIs:...`, `耗时:...`)
> **输出**: 面向最终用户的《操作手册》
>
> **转换规则**:
> 1. **去除噪音**: 彻底删除 "测试耗时", "Param", "APIs" 等技术字段（除非用户明确要求显示）。
> 2. **重写描述**: 将 "步骤：导航菜单-系统配置(成功)" 改写为指导性语言 "### 2.1 进入系统配置\n点击左侧菜单栏的【系统配置】..."。
> 3. **保留截图**: **必须**保留所有 `![snapshot](...)` 链接，且保持原有顺序。
> 4. **排版**: 使用清晰的 Markdown 标题层级。
