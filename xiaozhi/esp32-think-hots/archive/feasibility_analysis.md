# 技术可行性分析: Think-Shots (碎碎念收集器)

## 1. 核心挑战：Wi-Fi 与 蓝牙共存 (Coexistence)
ESP32-S3 仅有一套射频（Radio）系统，同时开启 Wi-Fi 和 蓝牙（尤其是 A2DP 经典蓝牙）会产生竞争。

### 风险点
- 在 Wi-Fi 高速上传音频数据时，蓝牙耳机的提示音可能会出现严重的断音或卡顿。
- 功耗会显著上升。

### 解决方案：异步时分复用 (Asynchronous TDM)
- **录音阶段**：关闭或置低 Wi-Fi 优先级，全力保证 I2S 采样和蓝牙反馈。
- **上传阶段**：录音结束并暂存 PSRAM/SD 后，暂停蓝牙音频流，利用 Wi-Fi 全速上传。
- **结论**：**可行**，但需要精细的软件调度。

## 2. 语音链路与 HFP (Hands-Free Profile)
- **挑战**：通过蓝牙耳机麦克风录音，需要 ESP32 处于 **HFP HF (Hands-Free)** 角色。
- **技术点**：
  - **频率**：HFP 支持 CVSD (8kHz) 或 mSBC (16kHz Wideband Speech)。对于 Whisper ASR，16kHz 已经足够。
  - **共存**：HFP 是双向链路，与 Wi-Fi 同步时的竞争比 A2DP Source 更激烈。
- **唤醒词 (Wake-word)**：
  - **方案**：采用 **ESP-SR** (Skainet) 框架，在双核 S3 的其中一个核上运行轻量级 CNN 唤醒引擎。
  - **灵敏度**：需要根据“口袋内/桌面”等不同信噪比环境调优唤醒阈值。
- **结论**：**可行，但属于进阶开发**。建议第一步先实现本地唤醒+本地录音，第二步再攻克 HFP 耳麦录音。

## 3. 云端 AI 方案选型
| 维度 | OpenAI Whisper | Deepgram | Groq (Whisper-v3) |
| :--- | :--- | :--- | :--- |
| **转写质量** | 极高 (SOTA) | 优秀 | 极高 |
| **延迟 (Latency)** | 2-5s | < 500ms | < 800ms |
| **成本** | $0.006 / 分钟 | 约 $0.004 / 分钟 | 目前处于公测/极低成本 |
| **推荐理由** | 最全能，支持各种方言纠错 | 追求极致的“秒出文字” | 追求极速且低成本 |

**最终建议**：初期采用 **OpenAI Whisper API** 作为 ASR，配合 **GPT-4o-mini** 进行语境纠错与摘要，成本极低（每 1000 条碎碎念不到 1 元人民币）。

## 4. 总结
硬件成本 ($10-$15) 与 运营成本 (按需付费) 均在可接受范围内。
**下一步建议**：基于 ESP32-S3 开发板搭建 I2S 录音并上传至服务器的最小可行原型 (MVP)。
