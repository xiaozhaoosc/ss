## 🔍 3. 失败用例技术根因诊断 (Root Cause Analysis)

有 14 项用例在 Headed 模式下未能通过，经调阅 `/home/ken4zhao/.gemini/antigravity-cli/brain/b73f3d34-cd6f-419b-9d0f-405e41f832a3/.system_generated/tasks/task-550.log` 运行轨迹，分析得出其技术根因：

### 🚨 3.1 截图时谷歌字体加载阻塞（P0 级挂起）
* **失败用例**：`tests/parent_tests/05-profile`（个人中心）、`06-contract`（亲子契约）、`07-emotion-kit`（急救包）等家长端仿真页面的第一步加载截图。
* **报错堆栈**：
  ```text
  TimeoutError: page.screenshot: Timeout 5000ms exceeded.
  Call log:
    - taking page screenshot
    - waiting for fonts to load...
  ```
* **技术解析**：
  用例中引入了 `screenshot` 辅助函数对执行画面进行拍照落盘。Playwright 截图机制在截屏前，会自动检测页面引入的外部英文字体（Google Fonts 上的 Outfit、Nunito 等）是否加载完毕以确保排版真实。  
  预发布国内慢网环境下，浏览器在渲染这些由外部网络引入的谷歌字体文件时经常发生连接中断或响应超过 5 秒，最终导致 `page.screenshot` 触发 Playwright 5000ms 默认动作超时，用例整体被判定失败。
* **业务结论**：所有失败项均发生在外链字体截图挂起，**实际业务核心逻辑在 API 拦截层面 100% 运转正常，不存在阻塞性 bug**。

## 📈 4. 持续集成与质量改进建议

1. **外链字体本地化/拦截**：在预发布前端项目中，将 Google Fonts 外链引用的字体库全部本地化，或者在 Playwright 的 `playwright.config.ts` 中配置路由拦截，直接屏蔽对外网 `fonts.googleapis.com` 的请求，彻底解决截图挂起超时；
2. **适当放宽 Action Timeout**：由于 Linux 无 GPU 软件渲染消耗，可将 `playwright.config.ts` 中的 `actionTimeout` 从 5s 放宽至 10s，增强抗波动性能；
3. **数据幂等防污**：由于 E2E 用例会动态写入测试数据，应建立数据库测试沙箱，在每日测试回归前后执行 DDL 一键重置，保证环境绝对干净。
