## ✅ 第一阶段：硬件点亮 (Hardware Hello World)
收货后，请按以下顺序进行单元测试，确保每个模块都是好用的。

### 1. 环境准备
- [ ] **安装驱动**: 安装 USB 转串口驱动（通常是 CH340 或 CP210x）。
    - *检查方法*: 插上开发板，电脑设备管理器能看到 COM 口。
- [ ] **刷入固件**: 下载并烧录适配 **ESP32-S3** 的 MicroPython 固件。
- [ ] **安装 IDE**: 安装 [Thonny](https://thonny.org/) (新手推荐) 或 VS Code + Pymakr (进阶)。

### 2. 单元测试 (Unit Tests)
> ⚠️ **警告**: 不要一下子把所有线都接上！一个一个测！

- [ ] **Test 1: 点灯 (Blink)**
    - *目标*: 控制板载 LED 闪烁。
    - *目的*: 验证 MicroPython 环境正常，板子是活的。
- [ ] **Test 2: 联网 (Wi-Fi)**
    - *目标*: 连接家里 Wi-Fi 并打印 IP 地址。
    - *目的*: 验证天线信号。
- [ ] **Test 3: 视觉 (WS2812B)**
    - *接线*: 5V, GND, GPIO 48 (S3默认)。
    - *目标*: 让灯环亮起红色，然后变成彩虹色。
- [ ] **Test 4: 听觉 (DFPlayer)**
    - *准备*: SD卡格式化为FAT32，存入 MP3 文件夹和 `0001.mp3`。
    - *接线*: TX/RX 交叉连接到 ESP32。
    - *目标*: 听到喇叭播放声音。
- [ ] **Test 5: 触觉 (NFC)**
    - *接线*: SPI 接口 (SDA, SCK, MOSI, MISO, RST)。
    - *目标*: 手机/NFC卡片靠近，控制台打印出 UID。

## 💻 第二阶段：软件基础设施 (Software Infra)

### 0. 测试服务器配置推荐 (Server Specs)
鉴于 SmallSteps-Vue-Plus (Java) 和 EMQX 都是内存消耗大户，建议按以下规格准备云服务器或本地虚拟机。

| 配置档位 | CPU / 内存 | 硬盘 | 适用场景 | 优化建议 |
| :--- | :--- | :--- | :--- | :--- |
| **最低配** (Economy) | 2核 / 4GB | 40GB SSD | 仅供单人开发调试 | 必须开启 Swap (虚拟内存) 至少 4G；Java 启动参数需限制 `-Xmx512m`。 |
| **推荐配** (Standard) | 4核 / 8GB | 60GB SSD | 团队协作 / 演示环境 | 运行流畅，可同时跑多个 Python Worker 容器。 |

**操作系统建议**: Ubuntu 20.04/22.04 LTS 或 Debian 11 (Docker 兼容性最佳，避免使用 CentOS 7)。

### 1. 基础设施搭建
- [ ] **启动 Docker 环境**: 使用 `docker-compose.yml` 启动 EMQX, RabbitMQ, Postgres。
- [ ] **MQTT 调试**:
    - 使用 MQTTX 客户端连接本地 EMQX (端口 1883)。
    - 订阅 `device/+/cmd`，尝试发送消息，验证连通性。
- [ ] **后端跑通**:
    - 启动 Spring Boot 和 Python Worker。
    - 用 Postman 发送 POST 请求，验证 AI 拆解能否生成 JSON。

### 3. 后端架构参考 (Backend Reference)
以下是针对“小步”项目筛选的精准参考指南：

#### A. Spring Boot 业务底座：SmallSteps-Vue-Plus
*   **地址**: [Gitee](https://gitee.com/dromara/SmallSteps-Vue-Plus) | [GitHub](https://github.com/dromara/SmallSteps-Vue-Plus)
*   **核心价值**: 解决“用户-角色-权限”和“多端登录”的脏活累活。
*   **重点参考模块**:
    *   `ruoyi-common-satoken`: 教科书级的 Token 鉴权、多端登录。
    *   `ruoyi-common-oss`: 封装 MinIO/OSS 接口，用于录音上传。
    *   `ruoyi-admin`: 规范的 System Controller 写法。

#### B. IoT 架构设计参考：ThingsBoard (Java)
*   **地址**: [GitHub](https://github.com/thingsboard/thingsboard)
*   **核心价值**: 学习其 **API 设计哲学** (不要直接用代码)。
*   **Topic 设计规范**:
    *   上报遥测: `v1/devices/me/telemetry` (e.g. `{battery: 80}`)
    *   上报属性: `v1/devices/me/attributes` (e.g. `{firmware: 1.0}`)
    *   RPC 指令: `v1/devices/me/rpc/request/+`

#### C. AI 服务参考：Langchain-Chatchat
*   **地址**: [GitHub](https://github.com/chatchat-space/Langchain-Chatchat)
*   **核心价值**: 规范的 FastAPI + LangChain 结构。
*   **参考点**: `server/api.py` (流式接口封装), `configs/` (Prompt 管理)。

## 📝 连线备忘录 (Wiring Memo - ESP32-S3)
> **⚠️ 注意**: DFPlayer 的 VCC 建议接 **5V**，接 3.3V 可能会导致声音小或不稳定。

| 模块 | 引脚名称 | ESP32-S3 GPIO | 备注 |
| :--- | :--- | :--- | :--- |
| **WS2812B** | DIN | **GPIO 48** | S3 板载 RGB 也是此脚 |
| **DFPlayer** | RX | **GPIO 17** | 接 ESP 的 TX (交叉连接) |
| **DFPlayer** | TX | **GPIO 18** | 接 ESP 的 RX (交叉连接) |
| **RC522** | SDA (SS) | **GPIO 5** | 片选 (CS) |
| **RC522** | SCK | **GPIO 6** | 时钟 |
| **RC522** | MOSI | **GPIO 7** | 数据输入 |
| **RC522** | MISO | **GPIO 2** | 数据输出 |
| **RC522** | RST | **GPIO 4** | 复位 |
