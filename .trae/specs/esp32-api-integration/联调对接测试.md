# 联调对接测试文档

## 1. 测试概述

本文档定义了 Small Steps 项目中 ESP32 硬件终端与后端 API 服务之间的联调对接测试计划，包括测试环境搭建、测试用例设计和执行流程。

## 2. 测试环境

### 2.1 硬件环境

- **ESP32 开发板**: ESP32-S3
- **网络设备**: WiFi 路由器
- **计算机**: 用于运行 API 服务和 MQTT Broker

### 2.2 软件环境

- **API 服务**: Spring Boot 应用
- **MQTT Broker**: EMQ X 或 Mosquitto
- **数据库**: PostgreSQL
- **ESP32 固件**: MicroPython
- **测试工具**: MQTT.fx 或 MQTT Explorer

## 3. 测试准备

### 3.1 环境搭建

1. **启动 MQTT Broker**:
   ```bash
   # 使用 Docker 启动 EMQ X
   docker run -d --name emqx -p 1883:1883 -p 8083:8083 emqx/emqx
   ```

2. **启动 API 服务**:
   ```bash
   # 进入 API 项目目录
   cd smallsteps-api
   # 构建并运行
   mvn spring-boot:run
   ```

3. **配置 ESP32**:
   - 烧录 MicroPython 固件
   - 上传通信模块代码
   - 配置 WiFi 和 API 信息

### 3.2 测试工具准备

- **MQTT 客户端**: 用于监控 MQTT 消息
- **API 测试工具**: Postman 或 curl
- **日志查看工具**: 用于查看设备和服务器日志

## 4. 测试用例

### 4.1 设备连接测试

#### 测试目标
验证 ESP32 能够成功连接到 API 服务和 MQTT Broker。

#### 测试步骤
1. 启动 ESP32 设备
2. 查看设备日志
3. 验证设备是否成功连接到 WiFi
4. 验证设备是否成功登录 API 服务
5. 验证设备是否成功连接到 MQTT Broker

#### 预期结果
- ESP32 成功连接到 WiFi
- ESP32 成功登录 API 服务并获取认证信息
- ESP32 成功连接到 MQTT Broker

### 4.2 设备状态上报测试

#### 测试目标
验证 ESP32 能够成功上报设备状态到 API 服务。

#### 测试步骤
1. 确保 ESP32 已连接到 MQTT Broker
2. 订阅设备状态主题 `devices/{device_id}/status`
3. 查看 ESP32 发送的状态消息
4. 验证 API 服务是否接收到状态消息
5. 验证状态数据是否正确存储到数据库

#### 预期结果
- ESP32 定期发送设备状态消息
- MQTT 客户端能够接收到状态消息
- API 服务能够正确处理状态消息
- 状态数据能够正确存储到数据库

### 4.3 任务指令下发测试

#### 测试目标
验证 API 服务能够成功下发任务指令到 ESP32。

#### 测试步骤
1. 确保 ESP32 已连接到 MQTT Broker
2. 通过 API 发送任务指令
3. 查看 ESP32 日志
4. 验证 ESP32 是否接收到任务指令
5. 验证 ESP32 是否执行任务指令
6. 验证 ESP32 是否发送响应消息

#### 预期结果
- API 服务成功发送任务指令
- ESP32 成功接收到任务指令
- ESP32 成功执行任务指令
- ESP32 成功发送响应消息

### 4.4 网络异常处理测试

#### 测试目标
验证系统在网络异常情况下的可靠性。

#### 测试步骤
1. 确保 ESP32 已连接到网络和 MQTT Broker
2. 断开网络连接
3. 等待一段时间
4. 恢复网络连接
5. 验证 ESP32 是否自动重连
6. 验证通信是否恢复正常

#### 预期结果
- ESP32 检测到网络断开
- ESP32 尝试重新连接网络
- 网络恢复后，ESP32 成功重连
- 通信恢复正常，能够继续上报状态和接收指令

### 4.5 多设备并发测试

#### 测试目标
验证系统在多设备并发情况下的性能和稳定性。

#### 测试步骤
1. 准备多个 ESP32 设备
2. 同时启动所有设备
3. 验证所有设备都能成功连接
4. 同时向所有设备发送任务指令
5. 验证所有设备都能正常响应

#### 预期结果
- 所有设备都能成功连接到系统
- 系统能够同时处理多个设备的请求
- 所有设备都能正常接收和执行任务指令
- 系统性能稳定，没有出现明显延迟
