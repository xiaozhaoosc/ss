# Small Steps 项目规则文档

## 1. 项目概述

### 1.1 项目简介
Small Steps（小步）是一个针对 ADHD 儿童的行为习惯辅助系统，通过 AI 极简拆解（降低认知负荷）+ 实体玩偶锚点（环境线索外化）+ CBT 专家系统（情绪行为干预），将混乱的生活"切碎"成无痛的微步骤，帮助多动家庭重建秩序与连接。

### 1.2 核心价值
- **对于孩子**：把枯燥的生活变成 RPG 游戏，万物皆可互动
- **对于家长**：提供"情绪防爆盾"和"育儿脚手架"，降低教养压力

### 1.3 产品架构
产品由 App（软件）、Hardware（硬件）和 Cloud（云脑）三部分构成闭环：
- **App 端**：任务粉碎机、心声回响、家长控制台
- **硬件端**：ESP32 小步玩偶、NFC 场景贴纸、勇气手环
- **AI 中台**：基于 Barkley/Greene 理论的垂类模型

## 2. 技术栈

### 2.1 后端技术
- **框架**：Java Spring Boot（基于 RuoYi-Vue-Plus）
- **数据库**：PostgreSQL
- **容器化**：Docker

### 2.2 前端技术
- **Web 前端**：Vue.js + TypeScript + Vite
- **移动应用**：uni-app + Vue.js

### 2.3 硬件技术
- **平台**：ESP32
- **语言**：MicroPython
- **通信**：MQTT / WebSocket

### 2.4 工具链
- **版本控制**：Git
- **容器管理**：Docker Compose
- **自动化测试**：Playwright
- **技能系统**：Anthropics Skills + 自定义技能

## 4. 开发规范

### 4.1 代码风格
- **后端**：遵循 Java 代码规范，使用 IDE 格式化
- **前端**：遵循 Vue 代码规范，使用 ESLint + Prettier
- **硬件**：遵循 MicroPython 代码规范，注重可读性

### 4.2 版本控制
- **分支管理**：
  - `main`：主分支，保持稳定
  - `develop`：开发分支
  - `feature/*`：功能分支
  - `bugfix/*`： bug 修复分支
- **提交规范**：使用语义化提交信息

### 4.3 命名规范
- **文件命名**：小写字母 + 下划线（后端），小驼峰（前端）
- **变量命名**：小驼峰命名法
- **类命名**：大驼峰命名法
- **常量命名**：全大写 + 下划线

### 4.4 文档规范
- **API 文档**：使用 Swagger 或 Apifox
- **技术文档**：使用 Markdown 格式
- **需求文档**：存放在 `参考文档/` 目录

## 5. 开发流程

### 5.1 需求管理
1. 需求分析和拆解
2. 创建任务文档
3. 技术可行性评估

### 5.2 开发流程
1. 从 `develop` 分支创建功能分支
2. 编写代码和测试
3. 提交代码并创建 Pull Request
4. 代码审查
5. 合并到 `develop` 分支
6. 定期从 `develop` 分支合并到 `main` 分支

### 5.3 测试流程
- **单元测试**：开发人员编写
- **集成测试**：使用 Playwright 进行 E2E 测试
- **硬件测试**：在实际设备上测试

## 6. 部署流程

### 6.1 本地开发环境
1. 启动 Docker 容器（数据库、Redis 等）
2. 启动后端服务
3. 启动前端开发服务器

### 6.2 生产部署
1. 使用 Docker Compose 构建和部署
2. 配置环境变量
3. 启动所有服务
4. 监控服务状态

### 6.3 硬件部署
1. 编译 MicroPython 固件
2. 烧录到 ESP32 设备
3. 配置网络和连接信息
